Use the **source-available TypeScript, Rust, and Python SDKs** with your own keys
and RPC connection. You need a compatible Swig deployment from your operator;
[Environment Setup](/evm/setup) explains how to obtain its details.

## Choose your language

First [check out the latest SDK source](/evm/setup#set-up-the-examples).
Run the matching setup command from the repository root:

<CodeGroup>

```bash TypeScript
cd evm/typescript
bun install --frozen-lockfile
```

```bash Rust
cd evm
cargo build --locked -p swig-evm --examples
```

```bash Python
cd evm/python
uv sync --locked
```

</CodeGroup>

TypeScript uses Viem, Rust uses Alloy, and Python uses Web3.py and eth-account.
The guides keep the same language labels for each scenario. Swig supplies
contract bindings, permission codecs, and a small smart-account adapter.

## Get started

1. [Set up your environment](/evm/setup) and connect to a compatible deployment.
2. [Create a wallet](/evm/create-wallet) with a root authority and fund its vault.
3. [Add a spending role](/evm/add-role) and [inspect its permissions](/evm/read-role).
4. [Send a transfer](/evm/send-transfer) with the role's key paying gas.
5. [Sponsor a transfer](/evm/send-sponsored-transfer) through a compatible bundler and paymaster.

## Sponsored transfers

Sponsored operations currently use **already deployed accounts and EntryPoint
v0.9**, with one call per operation. The shared beacon requires a compatible
bundler policy. See [Send a Sponsored Transfer](/evm/send-sponsored-transfer)
for provider requirements and the tested SDK versions.

## Reference and next steps

The shared beacon selects the implementation used by every wallet in the fleet.
It lets an operator upgrade that fleet without individual
user upgrade transactions. [Bundler Compatibility](/evm/bundler-compatibility)
covers account registration and handling operations queued during an upgrade.

Building on Solana? Use the [Solana Protocol SDK](/solana).
