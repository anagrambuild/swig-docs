The Developer SDK registers a Devnet email wallet app using the project API key on your server. The end user verifies their email in the browser using the public IdP routes.

## Register an email wallet app

`POST /identity/api/email-wallet-apps/ensure` creates the registration or returns the same client ID when all settings match. Enable the project's email provider first.

```typescript
const payer = await swig.paymaster.getBalance({ network: "devnet", kind: "api" });
if (!payer.configured) throw new Error("Configure a project API paymaster first");

const app = await swig.idp.ensureEmailWalletApp({
  network: "devnet",
  callbackUrl: "http://localhost:4181/auth/callback",
  walletTemplateId,
  agentPublicKey,
  projectPaymasterAddress: payer.address,
});
```

| Input | Meaning |
| :--- | :--- |
| `network` | Use `devnet` in the SDK or `NETWORK_DEVNET` in ProtoJSON. |
| `callbackUrl` | Exact HTTPS browser callback URL. HTTP is supported on localhost and 127.0.0.1. |
| `walletTemplateId` | Project wallet template with an at-creation owner and an at-creation trading agent with recurring SOL and Devnet USDC limits. |
| `agentPublicKey` | Public Ed25519 key of the agent. Keep its signing key in your app. |
| `projectPaymasterAddress` | Optional active API paymaster owned by this project. Its Devnet balance covers setup fees and rent, and setup transactions count toward the project's sponsorship allowance. Omit this field to use the dedicated IdP paymaster. |

The response contains the public `clientId`, registered callback, template ID, agent public key and, when selected, project paymaster address. The verified email determines the wallet address before the user approves creation.

| Error | Meaning |
| :--- | :--- |
| `FAILED_PRECONDITION` | The template is incompatible or the selected paymaster is unavailable for this project. |
| `NOT_FOUND` | The email provider is unavailable or disabled. |
| `ALREADY_EXISTS` | The same callback already has different settings or the app is disabled. |

## Who owns identity integration

The [IDP SDK](/idp-sdk) owns identity integration guidance: OAuth, email OTP,
SMS OTP, session handling, and how a completed login becomes a Swig session.

<Warning>
  The currently published IDP SDK defaults still target retired
  `/identity/api/*` routes and its endpoint model does not fully represent the
  public OTP and setup contract below. Treat the route table on this page as
  the current backend contract until the IDP SDK is refreshed.
</Warning>

Once a user has a session, the Developer SDK picks it up:

<CodeGroup dropdown>

```typescript TypeScript
const wallet = swig.wallets.fromIdpSession(session);
```

```python Python
wallet = swig.wallets.from_idp_session(session)
```

</CodeGroup>

Use the returned client ID in the browser email flow. Keep the project API key on the server.

## Public IdP routes

These routes are public. They are listed here as the current backend contract.

| Method | Route |
| :--- | :--- |
| `POST` | `/identity/public/auth/start` |
| `POST` | `/identity/public/auth/email/start` |
| `POST` | `/identity/public/auth/email/verify` |
| `POST` | `/identity/public/auth/email/resend` |
| `POST` | `/identity/public/auth/sms/start` |
| `POST` | `/identity/public/auth/sms/verify` |
| `POST` | `/identity/public/auth/sms/resend` |
| `POST` | `/identity/public/setup/sponsor` |
| `GET` / `POST` | `/identity/public/callback/{provider}` |
| `GET` | `/identity/public/verify_jwt/jwks.json` |
| `GET` | `/identity/public/oidc/jwks.json` |

The JWKS routes are what you use to verify identity tokens server-side.
For client wallet lookup and status, see the [public wallet boundary](/developer-api/wallets#public-client-boundary).

## Why this matters

- Do not send a Swig API key to these routes. They are not API-key guarded, and
  doing so leaks a server credential into a client-facing call path.
- Do not model login as a server-to-server call. The user's client completes the
  flow; your server verifies the result.
- Organization-provider configuration belongs to the developer portal.

## What is not here

There is no `/identity/api/auth/passkey/start` route. If you have an
integration pointed at that path, it is targeting an endpoint that does not
exist in the current backend.
