The Ramp API buys and sells crypto against fiat through a ramp provider. One
service covers both directions: direction is carried by the `buy` or `sell`
order you send, not by the route, so the two cannot disagree. Assets are Solana
only.

## Auth

Use an API key:

```text
Authorization: Bearer sk_your_api_key
```

## Routes

| Method | Route |
| :--- | :--- |
| `GET` | `/wallet/api/ramp/options` |
| `POST` | `/wallet/api/ramp/quotes` |
| `POST` | `/wallet/api/ramp/orders` |
| `GET` | `/wallet/api/ramp/orders/{order_id}` |
| `POST` | `/wallet/api/ramp/orders/{order_id}/transfer/prepare` |
| `POST` | `/wallet/api/ramp/orders/{order_id}/transfer/submit` |

## Required fields

| Field | Type | Description |
| :--- | :--- | :--- |
| `configurationId` | string | The organization's ramp configuration id |
| `environment` | enum | `RAMP_ENVIRONMENT_SANDBOX` or `RAMP_ENVIRONMENT_PRODUCTION` |

On the options route these are query parameters; on the quote and order routes
they are body fields. Order reads and transfer actions identify the order in the
route path and take **no** environment — it is a property of the stored order.

The provider environment is not a Solana cluster. A sandbox order still settles
on mainnet.

## Amounts

Amounts are unsigned integers in the smallest unit the thing has, encoded as
decimal strings:

| Type | Fields | Unit |
| :--- | :--- | :--- |
| `FiatAmount` | `currencyCode`, `minorUnits` | cents for USD, whole yen for JPY |
| `CryptoAmount` | `asset`, `baseUnits` | the asset's base units |

An amount finer than the currency's minor unit is refused, never rounded. Read
`AssetOption.decimals` and `FiatCurrencyOption.exponent` from the options route
to build a valid value.

A crypto asset is one of two shapes. Native SOL carries no mint:

```json
{ "sol": {} }
{ "token": { "mint": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v" } }
```

`exchangeRate` is the one decimal string that is not an integer: a rate is a
ratio and has no minor unit to scale to. It is display-only.

## Get options

`GET /wallet/api/ramp/options`

Query parameters:

| Parameter | Type | Description |
| :--- | :--- | :--- |
| `configurationId` | string | Required |
| `environment` | enum | Required |
| `direction` | enum | `RAMP_DIRECTION_BUY` or `RAMP_DIRECTION_SELL` |
| `countryCode` | string | ISO 3166-1 alpha-2. Omit to list countries alone |
| `fiatCurrencyCode` | string | ISO 4217 alpha-3, optional filter |

Response fields:

| Field | Type | Description |
| :--- | :--- | :--- |
| `countries` | array | `code`, `name`, and `subdivisions` of `code` and `name` |
| `fiatCurrencies` | array | `currencyCode` and `exponent` |
| `paymentMethods` | array | Opaque provider payment-method identifiers |
| `assets` | array | `asset`, `name`, `decimals`, and an optional `iconUrl` |

`decimals` is Swig's own value for the asset, not the provider's.

## Get quotes

`POST /wallet/api/ramp/quotes`

```json
{
  "configurationId": "018f-config",
  "environment": "RAMP_ENVIRONMENT_SANDBOX",
  "location": { "countryCode": "US", "subdivisionCode": "US-CA" },
  "buy": {
    "spend": { "currencyCode": "USD", "minorUnits": "10000" },
    "receive": { "token": { "mint": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v" } }
  }
}
```

Send `sell` instead of `buy` for the other direction:

```json
{
  "sell": {
    "sell": { "asset": { "sol": {} }, "baseUnits": "1000000000" },
    "receiveFiatCurrencyCode": "USD"
  }
}
```

The response carries `quotes`, each with a `route` of `provider` and
`paymentMethod`, plus a `buy` or `sell` arm holding the priced amounts, the
`totalFee`, and the `exchangeRate`.

<Warning>
  Quotes carry no identifier and must never be cached. The provider mints none
  and documents that they must not be reused, so the route you choose is
  re-priced when the order is created.
</Warning>

## Create an order

`POST /wallet/api/ramp/orders`

```json
{
  "requestId": "0f1c6f1e-8b5a-4d1b-9f0d-3a2f6a1b7c44",
  "configurationId": "018f-config",
  "environment": "RAMP_ENVIRONMENT_SANDBOX",
  "context": {
    "customerId": "your-customer-id",
    "swigConfigAddress": "SwigConfigAddress",
    "network": "NETWORK_MAINNET",
    "location": { "countryCode": "US" }
  },
  "route": { "provider": "PROVIDER", "paymentMethod": "CARD" },
  "buy": {
    "spend": { "currencyCode": "USD", "minorUnits": "10000" },
    "receive": { "token": { "mint": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v" } }
  }
}
```

`requestId` is your idempotency key and is unique within the configuration.
Repeating it returns the stored order; repeating it with different inputs is
refused with `ALREADY_EXISTS`. Mint it before the first attempt and reuse it
across retries.

The response is `{ "order": ... }`. An order carries `id`, `status`,
`createdAt`, `updatedAt`, and a `buy` or `sell` detail arm.

## Read an order

`GET /wallet/api/ramp/orders/{order_id}`

Returns `{ "order": ... }`. A read of a non-final order refetches the provider's
record first, so polling this route is what advances the order and fills in the
deposit address a sell needs.

| Status | Meaning |
| :--- | :--- |
| `RAMP_ORDER_STATUS_CREATING` | The provider session is being created |
| `RAMP_ORDER_STATUS_CREATION_UNCERTAIN` | The provider call gave no answer that can be trusted; it is never retried |
| `RAMP_ORDER_STATUS_AWAITING_CUSTOMER` | Waiting on the customer at the provider |
| `RAMP_ORDER_STATUS_AWAITING_TRANSFER` | Sell only: waiting for the crypto transfer |
| `RAMP_ORDER_STATUS_PROCESSING` | The provider is processing |
| `RAMP_ORDER_STATUS_SETTLING` | Funds are moving |
| `RAMP_ORDER_STATUS_SETTLED` | Complete |
| `RAMP_ORDER_STATUS_DECLINED` | The provider declined |
| `RAMP_ORDER_STATUS_CANCELLED` | Cancelled |
| `RAMP_ORDER_STATUS_FAILED` | Failed |
| `RAMP_ORDER_STATUS_REFUNDED` | Refunded; this is the one transition reachable out of `SETTLED` |

A buy carries the quote and an optional `launchUrl`. A sell also carries
`deposit` once the provider assigns one, and `transfer` once one is prepared.

<Warning>
  A `launchUrl` is a user-specific session URL. Hand it to the customer who owns
  the order and keep it out of logs and analytics.
</Warning>

## Prepare a transfer

`POST /wallet/api/ramp/orders/{order_id}/transfer/prepare`

Sell only. Call it once the order reaches `AWAITING_TRANSFER` and carries a
`deposit`.

```json
{
  "requesterAuthority": { "ed25519": { "publicKey": "RequesterPublicKey" } },
  "feePayer": "FeePayerPublicKey"
}
```

The response is `{ "preparedTransfer": ... }`, carrying the `transfer`, the
`preparedTransaction` to sign, and the canonical `deposit`. The transfer is
built from the provider's own record rather than the quote, so a repriced amount
funds the deposit correctly. `transfer.expiresAt` is the prepared blockhash's
lifetime.

## Submit a transfer

`POST /wallet/api/ramp/orders/{order_id}/transfer/submit`

```json
{
  "transferId": "018f-transfer",
  "signedTransaction": "base64-signed-transaction"
}
```

Returns `{ "transfer": ... }` with a `state` of `TRANSFER_STATE_PREPARED`,
`SUBMITTED`, `LANDED`, `FAILED`, or `EXPIRED`, and a `solanaSignature` once one
exists. A transfer settles only at `confirmed` or better, so a `processed`
signature still reads as in-flight.

The prepared transaction is handed over exactly once. If you broadcast it and
then lose it, submit again with an empty `signedTransaction` to resolve the
attempt that is already live.

## Errors

Validation failures return `INVALID_ARGUMENT`. A configuration that is disabled
or not approved returns `FAILED_PRECONDITION`, and that stops orders already in
flight, not only new ones. See [Errors](/developer-api/errors).

## SDK equivalent

The [Developer SDK](/developer-sdk/ramp) wraps these routes as `swig.ramp` in
TypeScript and Python.
