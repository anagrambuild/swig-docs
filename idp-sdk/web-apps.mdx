For browser apps, use the `/web` entry point. This is the browser-safe surface
that does not depend on Expo or React Native modules.

## Main integration surface

Use:

- `createSwigWebClient()`
- `getOAuthStartUrl()`
- `redirectToOAuth()`
- `completeOAuthFromUrl()`
- `getSession()`
- `getPersistedSession()`
- `logout()`
- `listProviders()`

## Basic shape

<CodeGroup dropdown>

```ts TypeScript
import { Network, createSwigWebClient } from "@swig-wallet/expo-idp-sdk/web";

const swig = createSwigWebClient({
  redirectUri: `${window.location.origin}/auth/callback`,
  network: Network.Devnet,
});

await swig.redirectToOAuth({
  provider: "google",
  clientId: "your-client-id",
  policyId: "your-policy-id",
  flow: "role",
});
```

</CodeGroup>

In your callback route:

<CodeGroup dropdown>

```ts TypeScript
import { createSwigWebClient } from "@swig-wallet/expo-idp-sdk/web";

const swig = createSwigWebClient({
  redirectUri: `${window.location.origin}/auth/callback`,
});

const session = await swig.completeOAuthFromUrl(window.location.href);
```

</CodeGroup>

## What this path is best for

- browser-based OAuth redirects
- apps that want full control over callback routes
- apps that need custom browser storage adapters

## Storage and callback behavior

- session persistence defaults to `window.localStorage`
- you can pass a custom `storage` adapter
- `completeOAuthFromUrl()` parses the callback and saves the session

## Email OTP with an agent role

The browser preview is available from the public SDK source. Use it with the matching scoped email wallet release on your IdP host.

```sh
npm install --legacy-peer-deps git+https://github.com/anagrambuild/swig-idp-sdk.git#3d5cd503bb5e25a16f16e51bbb4848ed33325c76
```

Register the Devnet app on your server and supply its public client ID to the browser. Your server creates a single-use state and OIDC nonce for each login. [Email wallet app registration](/developer-api/identity#register-an-email-wallet-app)

```typescript
const email = swig.auth.email;
const challenge = await email.start({ email: emailAddress, clientId, state, oidcNonce });
const result = await email.verify({ challengeId: challenge.challengeId, code });
if (result.status === "approval_required" && result.wallet) {
  // Show the derived address and agent limits before the user approves creation.
  showPreview(result.wallet);
}
```

Call `email.approve({ challengeId: challenge.challengeId })` directly from the user's click. A returning user whose agent role already matches can receive `complete` from `verify`. In both cases, verify the returned ID token's signature, issuer, audience, expiry and nonce on your server, and match the state to the initiating browser session.
