The Swig IDP SDK is for apps that want users to sign in first, then continue
with a Swig session.

It lives in the separate `swig-idp-sdk` repo and currently ships as
`@swig-wallet/expo-idp-sdk`.

## Use this SDK when

- users should sign in with OAuth, email OTP, or SMS OTP
- your app needs a Swig session after authentication
- you are building a web app or an Expo / React Native app
- authentication should stay inside Swig's isolated-host flow

## Do not use this SDK for

- transaction preparation
- paymaster operations
- direct protocol instruction building
- developer-portal policy management

Use [Swig Developer SDK](/developer-sdk) for hosted wallet operations after
login, or [Swig Protocol SDK](/reference) for direct protocol integration.

## Main API surface

Expo and React Native apps use:

- `SwigIdpProvider`
- `useSwigIdp()`
- `startOAuth()`
- `startEmailOtp()`
- `startSmsOtp()`
- `listProviders()`

Browser apps use the `/web` entry point:

- `createSwigWebClient()`
- `getOAuthStartUrl()`
- `redirectToOAuth()`
- `completeOAuthFromUrl()`
- `getSession()`
- `getPersistedSession()`
- `logout()`
- `listProviders()`

## What happens after login

The output of these flows is a Swig session your app can use in the next layer
of the product:

- continue into the **Swig Developer SDK** if your backend will prepare wallet
  actions
- continue into the **Swig Protocol SDK** if your app talks to the protocol
  directly

## Backend dependencies

The SDK is backed by Swig identity endpoints such as:

- `/identity/api/providers`
- `/identity/api/auth/start`
- `/identity/api/auth/email/start`
- `/identity/api/auth/sms/start`
- `/identity/api/signup`
- `/identity/api/session`

It also relies on isolated-host redirect flows for secure auth handoff.

## Security boundary

The supported mobile auth paths open the isolated host in a system auth
session. The host app should not embed these flows in a `WebView`.

This boundary matters because the isolated host owns the OAuth redirect, OTP
entry, verification code handling, and callback JWT exchange.
