## Introduction

Template reads return the current saved role definitions and wallet layouts for
the authenticated project. Use them for an application's Policies section or to
review a design before creating wallets. They do not describe permissions already
applied to an on-chain wallet.

TypeScript exposes the role and wallet template clients. These reads require the
normal project API key, have no pagination, and are independent of network.

## SDK examples

### List role and wallet templates

Use the server client from [Client setup](/developer-sdk/integration-paths).

```typescript TypeScript
const roles = await swig.roleTemplates.list();
const wallets = await swig.walletTemplates.list();
```

**SDK returned structure** (illustrative):

```typescript
// roles
[{ id: "owner", name: "User's key", keySource: "atCreation", permissions: [{ type: "all" }] }]

// wallets
[{
  id: "wallet-template",
  name: "Application wallet",
  description: "",
  initialRole: { id: "owner", name: "User's key", keySource: "atCreation", permissions: [{ type: "all" }] },
  additionalRoles: [],
}]
```

Empty arrays mean no templates are saved. Failed reads raise errors. Wallet
reads resolve referenced roles to their latest definitions in one database
snapshot and preserve the saved role order.

### Get one role or wallet template

Fetch by the ID returned from [template creation](/examples/dev-portal/create-policy).

```typescript TypeScript
const role = await swig.roleTemplates.get(roleTemplateId);
const wallet = await swig.walletTemplates.get(walletTemplateId);
```

**SDK returned structure**: `role` is one element of the role list above;
`wallet` is one element of the wallet list above. Stored keys include
`keySource: "stored"` and `authority`, such as
`{ ed25519: { publicKey: agentPublicKey } }`. Permission objects are typed SDK
`AddRoleAction` values and can be used when preparing role transactions.

### Read a legacy policy

Existing Python and Rust integrations retain the initial-role policy lookup.
Use the new TypeScript template clients for the full composed layout.

<CodeGroup>
```typescript TypeScript
const policy = await swig.wallets.getPolicy(policyId);
```
```python Python
policy = await swig.wallets.get_policy(policy_id)
```
```rust Rust
let policy = wallet.get_policy(&policy_id).await?;
```
</CodeGroup>

**SDK returned structure**: existing policy fields include `id`, `name`,
`description`, initial `authority` and `actions`, and recovery metadata. Legacy
stored action names such as `SolLimit` differ from typed SDK inputs such as
`solLimit`. Python and Rust keep their existing typed field sets.

## Input

| Operation | Parameter | Requirement | Meaning |
| :--- | :--- | :--- | :--- |
| `roleTemplates.get` | Role template ID | Required | Owned reusable role |
| `walletTemplates.get` | Wallet template ID | Required | Owned wallet layout |
| Both list methods | None | — | All current templates for the project |
| All methods | API key | Client setting | Normal project credential kept in private server configuration |

## Output

| Field | Type | Meaning |
| :--- | :--- | :--- |
| Role `id`, `name` | string | Stable identifier and current display name |
| Role `permissions` | `AddRoleAction[]` | Current explicit grants; amounts and windows are exact decimal strings |
| Role `keySource`, `authority` | Discriminated union | `atCreation` without authority, or `stored` with a direct public authority |
| Wallet `id`, `name`, `description` | string | Wallet template metadata |
| Wallet `initialRole`, `additionalRoles` | Role object / ordered array | Latest referenced role definitions |
| Wallet `rentClaimer` | Optional string | Configured rent recipient |
| Wallet `recovery` | Optional object | Guardian key source, authority when stored, label and delay in seconds |

Saved templates do not modify existing wallets. Read the
[confirmed role layout](/developer-sdk/add-roles-and-permissions#confirm-the-role)
and balances separately for on-chain status.

## Errors

| Error | Meaning |
| :--- | :--- |
| Project access unavailable | Invalid or disabled project API key. |
| Template not found | The requested ID is missing or belongs to another project. |
| Invalid stored template | A required role, authority, permission, or setting cannot be decoded; the read fails instead of returning a partial layout. |
| Read unavailable | Retry the read; do not display an empty policy list as a successful result. |
