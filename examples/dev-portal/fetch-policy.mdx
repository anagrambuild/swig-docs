## Introduction

A policy lookup returns the authority and action configuration saved for wallet
creation. Use it to inspect a template before creating a wallet or displaying its
setup in your application. It describes saved metadata, not a wallet's current
on-chain permissions.

TypeScript and Python expose this lookup. Your API key must have access to the
template; a wallet signature is not required.

## Input

| Parameter | Required | Description |
| :--- | :--- | :--- |
| `policyId` / `policy_id` | Yes | ID saved when [creating the template](/examples/dev-portal/create-policy) |
| API key | Client setting | Server credential with access to the template |

## Output

TypeScript names are shown below. Python exposes a `Policy` object with
snake_case top-level fields.

| Field | Type | Meaning |
| :--- | :--- | :--- |
| `id`, `name` | string | Template identifier and display name |
| `description` | string or null | Saved description |
| `authority` | object, null, or absent | Stored initial authority; your application supplies one when the template requires it |
| `actions` | array, optional | Saved action data for the initial user |
| `initialKeySource` | string, optional | Whether the initial key is stored or supplied at creation |
| `guardianEnabled`, `guardianAuthority`, `guardianKeySource`, `guardianDelaySeconds` | Optional compatibility fields | Retained recovery metadata; presence does not establish an available recovery flow |

This lookup does not return additional users saved in the portal. Store the
configuration needed to provision those roles in your application. Saved actions
use stored names and shapes; map them to typed [permission](/developer-sdk/permissions)
inputs when adding a role rather than forwarding them unchanged.

## Errors

| Failure | Cause | What to do |
| :--- | :--- | :--- |
| 401 or 403 | The API key is invalid or lacks access. | Check the server key and its resource access. |
| 404 | The policy ID is not found or is not visible to the caller. | Confirm the saved policy ID and organization access. |

## SDK example

Use the server client from [Client setup](/developer-sdk/integration-paths).

<CodeGroup>
```typescript TypeScript
const policy = await swig.wallets.getPolicy(policyId);
```

```python Python
policy = await swig.wallets.get_policy(policy_id)
```
</CodeGroup>

Pass the ID into [Create a wallet](/developer-sdk/create-wallets)
when ready. Use the [role list](/developer-sdk/add-roles-and-permissions#confirm-the-role)
to inspect permissions already on-chain.
