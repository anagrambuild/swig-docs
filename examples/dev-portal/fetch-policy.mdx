Read a policy to inspect the authority and actions saved for wallet creation.
Use the same Developer SDK client that prepares your wallet operations.
Reading a policy requires an API key with access to that policy; it does not
require a wallet signature.

## Before you begin

- Initialize the [TypeScript or Python client](/developer-sdk/integration-paths)
  on your server with an [API key](/examples/dev-portal/create-api-key).
- [Create a policy](/examples/dev-portal/create-policy) in the Developer Portal
  and copy its policy ID.

## Fetch a policy

The following examples use your initialized `swig` client and policy ID.

<CodeGroup dropdown>

```typescript TypeScript
const policy = await swig.wallets.getPolicy(policyId);

console.log(policy.id);
console.log(policy.name);
console.log(policy.description);
console.log(policy.authority);
console.log(policy.actions);
```

```python Python
policy = await swig.wallets.get_policy(policy_id)

print(policy.id)
print(policy.name)
print(policy.description)
print(policy.authority)
print(policy.actions)
```

</CodeGroup>

Both clients call `GET /wallet/policies/{policyId}` on the hosted API.
TypeScript returns the policy metadata directly; Python exposes a `Policy`
object and normalizes its top-level field names to snake case.

## Understand the result

The response describes stored configuration. For example, the TypeScript
client preserves the API's wallet-authority shape:

```json
{
  "id": "clx1234567890abcdef",
  "name": "user-wallet-policy",
  "description": "Standard user wallet with transfer limits",
  "initialKeySource": "WALLET_POLICY_KEY_SOURCE_STORED",
  "authority": {
    "ed25519": {
      "publicKey": "7xKXtg2CW87d97TXJSDpbD5jBkheTqA83TZRuJosgAsU"
    }
  },
  "actions": [
    { "type": "SolLimit", "amount": "1000000000" }
  ]
}
```

A policy can omit the authority so that your application supplies the initial
user at wallet creation. The `actions` list contains saved action data. See
[Permissions](/developer-sdk/permissions) for the meaning of each grant, its
units, and the Developer SDK inputs used when adding a role.

Policy response actions use stored names such as `SolLimit`; `roles.add()`
uses the typed SDK inputs shown in the reference, such as TypeScript
`{ type: 'solLimit', amount }` or Python `SolLimitAction(...)`. Map fields to
those inputs when building a role rather than forwarding stored action data
unchanged.

To inspect the authorities and permissions currently attached to a wallet,
use [Read Wallet State](/developer-sdk/wallet-reads#roles).

## Handle read errors

The TypeScript client throws `SwigDeveloperSdkError` for failed API requests:

```typescript
import { SwigDeveloperSdkError } from '@swig-wallet/developer-sdk';

try {
  const policy = await swig.wallets.getPolicy(policyId);
  console.log(policy.name);
} catch (error) {
  if (error instanceof SwigDeveloperSdkError) {
    console.error('Status:', error.statusCode);
    console.error('Code:', error.code);
  }
  throw error;
}
```

Check the API key and its resource access for `401` or `403` responses. For a
`404`, check that the policy ID exists and is visible to the caller. See
[Developer API Errors](/developer-api/errors) for other response statuses.

## Continue with the policy

Pass the policy ID when you [Create Wallets](/developer-sdk/create-wallets).
The SDK reads the policy as part of wallet preparation. Your application then
signs and submits the returned transactions.
