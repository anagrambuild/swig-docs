title: "Product Overview"
---

Swig spans four distinct product families. They live in different repos and solve different integration problems.

1. **Swig Protocol** in `swig-wallet`
2. **Swig Protocol SDK** across `swig-ts` and `swig-wallet`
3. **Swig Developer SDK** in `swig-ts/packages/developer-sdk`
4. **Swig IDP SDK** in `swig-idp-sdk`

## Choose the right section

| :--- | :--- |
| Understand the onchain protocol and repo layout | [Swig Protocol](/protocol) |

## 1. Swig Protocol

This is the onchain system itself. It lives in the `swig-wallet` repo and includes the Solana program plus the Rust crates that define protocol state, interfaces, instructions, assertions, and CLI tooling.

Use this product family when you need to understand:

- what the wallet program does on-chain
- how authorities, sessions, and actions work at the protocol layer
- how the Rust crates in `swig-wallet` fit together

## 2. Swig Protocol SDK

This is the protocol-adjacent SDK surface used to integrate with Swig wallets directly.

The code is split across:

- `swig-ts` for TypeScript packages such as `@swig-wallet/classic`, `@swig-wallet/kit`, `@swig-wallet/lib`, `@swig-wallet/coder`, and `@swig-wallet/mcp-server`
- `swig-wallet` for Rust packages such as `swig-sdk` and `swig-cli`

Use this product family when your app talks to the Swig protocol directly and you control wallet authorities and signing flows yourself.

## 3. Swig Developer SDK

This is the API-key product surface. It depends on the hosted Swig backend and requires access through the developer portal.

The primary package is:

- `@swig-wallet/developer-sdk` in `swig-ts/packages/developer-sdk`

Related lower-level clients still exist in the same monorepo:

- `@swig-wallet/developer` as the legacy developer SDK
- `@swig-wallet/api`

Use this product family when you want the backend to prepare wallet operations, return unsigned transactions, and let the client sign only what it must sign.

## 4. Swig IDP SDK

This is the identity and login-provider SDK. It lives in the separate `swig-idp-sdk` repo and currently ships as `@swig-wallet/expo-idp-sdk`.

Use this product family when you need:

- OAuth login
- email OTP or SMS OTP login
- web or Expo-native auth flows
- session creation against Swig identity endpoints

## Relationship between the four

- The **Swig Protocol** is the onchain foundation.
- The **Swig Protocol SDK** integrates with that protocol directly.
- The **Swig Developer SDK** uses hosted backend services to prepare and operate on Swig wallets through API-key access.
- The **Swig IDP SDK** handles end-user identity and session bootstrap for login-provider flows.
