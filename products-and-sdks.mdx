## Introduction

Choose the layer your application needs: hosted Solana wallet services,
direct protocol transactions, or user sign-in. The Developer SDK works with
Swig’s hosted API; Protocol SDK integrations own their RPC and transaction
construction. IdP adds browser or mobile authentication.

## Examples

### Start with hosted services

Install the Developer SDK for server-side wallet preparation and queries.

<CodeGroup>
```bash TypeScript
bun add @swig-wallet/developer-sdk
```
```bash Python
pip install --upgrade swig-developer-sdk
```
```bash Rust
cargo add swig-developer-sdk
```
</CodeGroup>

### Connect an authenticated session

For an application combining IdP and hosted services, bind the verified session to a wallet handle. This local helper makes no API request.

<CodeGroup>

```typescript TypeScript
const wallet = swig.wallets.fromIdpSession(session, { network: 'mainnet' });
```

```python Python
wallet = swig.wallets.from_idp_session(session, network="mainnet")
```

</CodeGroup>

## Input

| Need | Integration | Languages |
| :--- | :--- | :--- |
| Hosted Solana wallet operations and data | [Developer SDK](/developer-sdk/integration-paths) | TypeScript, Python, Rust; feature coverage varies by language. |
| Direct Solana instruction construction | [Solana SDK](/solana) | TypeScript and Rust. |
| Direct EVM wallet transactions | [EVM SDK](/evm) | Source-available TypeScript, Rust, and Python integrations. |
| Browser or mobile sign-in | [IdP SDK](/idp-sdk) | TypeScript; browser and Expo/React Native. |
| Assistant documentation or wallet tools | [Install MCP](/build-with-ai) | MCP-compatible client. |

## Output

| Integration | Result / responsibility |
| :--- | :--- |
| Developer SDK | Prepared transactions or typed hosted data. Your application owns user authorization, signing, and confirmation. |
| Protocol SDK | Direct protocol instructions/transactions. Your application owns RPC, authority integration, and submission. |
| IdP SDK | Authenticated session with wallet references. Verify the session before using it for application authorization. |

## Errors

| Error | Meaning |
| :--- | :--- |
| Wrong integration layer | Hosted preparation, direct protocol construction, and IdP authentication use different packages and contracts. |
| Feature unavailable in a language | Use the language tabs on the owning guide; do not infer parity from a shared product name. |
