title: "Instruction Builder"
---

The `SwigInstructionBuilder` is a fundamental component of the Swig SDK that handles the creation and management of Solana instructions for the Swig protocol.

## Overview

The instruction builder provides low-level functionality for creating various types of instructions needed to interact with Swig wallets on the Solana blockchain.

## Core Components

### Client roles

Pass a `Box<dyn ClientRole>` to select the authority implementation, such as
`Ed25519ClientRole` for an Ed25519 public key.

### SwigInstructionBuilder

```rust
pub struct SwigInstructionBuilder {
    swig_id: [u8; 32],
    swig_account: Pubkey,
    client_role: Box<dyn ClientRole>,
    payer: Pubkey,
    role_id: u32,
    reserved_create: Option<Instruction>,
}
```

## Authority Management

### Adding Authorities

```rust
pub fn add_authority_instruction(
    &mut self,
    new_authority_type: AuthorityType,
    new_authority: &[u8],
    permissions: Vec<ClientPermission>,
    current_slot: Option<u64>,
) -> Result<Instruction, SwigError>
```

Creates an instruction to add a new authority with specified permissions.

### Removing Authorities

```rust
pub fn remove_authority(
    &mut self,
    authority_to_remove_id: u32,
    current_slot: Option<u64>,
) -> Result<Instruction, SwigError>
```

Creates an instruction to remove an existing authority. The program rejects it
with `AuthorizationLockActive` while the role holds an active
[authorization lock](/protocol/authorization-locks), and otherwise also prunes
the role's inactive lock records.

### Replacing Authorities

```rust
pub fn replace_authority(
    &mut self,
    authority_to_replace_id: u32,
    new_authority_type: AuthorityType,
    new_authority: &[u8],
    permissions: Vec<ClientPermission>,
    current_slot: Option<u64>,
) -> Result<Vec<Instruction>, SwigError>
```

Creates instructions to replace an existing authority with a new one.

## Authorization Locks

These APIs target the Rust auth-lock draft, not the published 3.0.0 crates.
Use the source revisions in the [recipe](/examples/authorization_locks).

### Adding a Lock

```rust
pub fn add_authorization_lock(
    &self,
    asset_account: Pubkey,
    mint: [u8; 32],
    amount: u64,
    expiry_slot: u64,
    current_slot: Option<u64>,
) -> Result<Vec<Instruction>, SwigError>
```

Creates instructions that reserve `amount` of `asset_account` until
`expiry_slot`. Use the wallet address and an all-zero mint for native SOL, or a
token account owned by the wallet address and its mint. Token locks also pass
the mint account. With a `ProgramExecClientRole`, the returned instructions
start with the role's preceding instruction, which must pass the Swig config and
wallet address as its first two accounts.

### Removing a Lock

```rust
pub fn remove_authorization_lock(
    &self,
    lock_id: u32,
    rent_claimer: Option<Pubkey>,
    current_slot: Option<u64>,
) -> Result<Vec<Instruction>, SwigError>
```

Creates instructions that release a lock or prune an expired or fully captured
one. The wallet address is derived from the Swig account and passed
automatically. Pass the wallet's rent claimer when one is configured. To capture
a hold, the holder doesn't remove it: it spends from the locked account with
`sign_v2_instruction`, which lowers the lock by the amount spent.

## Examples

### Creating a New Swig Account

```rust
use swig_sdk::client_role::Ed25519ClientRole;

let mut instruction_builder = SwigInstructionBuilder::new(
    swig_id,
    Box::new(Ed25519ClientRole::new(authority_pubkey)),
    payer_pubkey,
    0
);

let create_ix = instruction_builder.build_swig_account()?;
```

### Adding a New Authority

```rust
let add_authority_ix = instruction_builder.add_authority_instruction(
    AuthorityType::Ed25519,
    new_authority_bytes,
    vec![Permission::All],
    Some(current_slot)
)?;
```
