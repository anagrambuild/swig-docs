The Swig protocol lives in the `swig-wallet` repo. This is the onchain foundation for Swig wallets on Solana.

## What lives in `swig-wallet`

The repository is not just one crate. It is a Rust workspace with separate packages for the program, interfaces, instructions, state handling, assertions, SDK, and CLI.

### Core workspace members

- `swig` in `program/`: the Solana program for the protocol
- `swig-interface` in `interface/`: shared protocol-facing types and interfaces
- `swig-compact-instructions` in `instructions/`: protocol instruction handling
- `swig-state` in `state/`: account state structures
- `swig-assertions` in `assertions/`: reusable assertion utilities
- `swig-sdk` in `rust-sdk/`: the Rust SDK surface
- `swig-cli` in `cli/`: command-line tooling for operating against the protocol

## What this layer is responsible for

This layer defines:

- how a Swig wallet is represented on-chain
- how the config account and wallet-address PDA work together
- how authorities and permissions are encoded
- how roles are keyed by `role_id`
- how sessions and wallet actions are validated
- how transactions are executed by the protocol

## Core mental model

At the program level, a Swig wallet is not just one signer.

- The main Swig config account stores the wallet ID, bump seeds, role count, and
  role counter.
- A separate wallet-address PDA is the address used during execution and
  signing flows.
- Each role binds a `role_id`, one authority, and one or more permission
  actions.
- `SignV2` is the general execution path that authenticates a role, checks its
  actions, and signs CPI execution through the wallet-address PDA.

## When to read this section

Use the protocol docs when you need to understand the system itself rather than just consume an SDK.

Typical reasons:

- you are auditing or reasoning about the protocol model
- you are working on the Rust crates in `swig-wallet`
- you need to understand how higher-level SDK behavior maps to the underlying program
