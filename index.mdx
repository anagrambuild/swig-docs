The Swig Developer SDK is a server-side toolkit for TypeScript, Python, and Rust.
It authenticates to Swig's hosted API, prepares wallet operations as unsigned
transactions, reads wallet state, and submits transactions your application
has signed.

## Choose your language

<CodeGroup>

```bash TypeScript
bun add @swig-wallet/developer-sdk
```

```bash Python
pip install swig-developer-sdk
```

```bash Rust
cargo add swig-developer-sdk@0.1.0
```

</CodeGroup>

Package `@swig-wallet/developer-sdk`, version `0.12.0`, includes
general role creation, ParticipantSet support, the unified ramp client,
[rent-claimer reads and preparation](/developer-sdk/rent-claimers), and
[DEX activity reads](/developer-sdk/dex-activity).

Published package `swig-developer-sdk`, version `0.11.0`, includes general role
creation, ParticipantSet support, and
[DEX activity reads](/developer-sdk/dex-activity). Requires Python 3.10 or later.

Rust `0.1.0` requires Rust 1.87 or later. See
[Rust setup](/developer-sdk/integration-paths#rust) for client configuration.

All three SDKs live in
[anagrambuild/swig-developer-sdk](https://github.com/anagrambuild/swig-developer-sdk)
and default to `https://api.onswig.com`.

## Get started

Start with an SDK language and an API key for your trusted server. Then choose
what each wallet role may do and how its authority will sign. An API key
authenticates hosted API requests; wallet operations still require the
appropriate authority's signature or approval proofs.

1. [Set up your client](/developer-sdk/integration-paths) and [create an API key](/examples/dev-portal/create-api-key).
2. [Choose permissions](/developer-sdk/permissions) and [create a wallet](/developer-sdk/create-wallets).
3. [Prepare a transfer](/developer-sdk/transfers-and-swaps) and obtain the authority's signature.
4. [Sponsor and submit](/developer-sdk/sponsor-and-submit) the signed transaction.

## Integration responsibilities

### SDK

- API-key authentication and retry behavior
- wallet creation and unsigned transaction preparation
- transfers, swaps, grouped operations, and custom instructions
- threshold ParticipantSet creation, role assignment, and approval compilation
- wallet, role, paymaster, and ramp reads
- DEX transaction history and latest-position reads
- fiat ramp order operations, buying and selling
- sponsorship of application-signed transactions and mainnet bundles
- local signing helpers for prepared transactions and participant approvals

### Your application

- end-user authentication and authorization
- frontend transport and user interfaces
- wallet-provider, passkey, hardware-wallet, or custody integration
- every private key and user authorization decision
- confirmation and finality tracking after submission

The server SDK returns unsigned prepared transactions and signature-request
metadata. Your application authorizes signing. TypeScript and Python helpers
use application callbacks. Rust also provides native signers that hold
application-supplied local keys. Signing helpers need no API key and make no
hosted request. Keep private keys in the runtime that owns signing.

## Wallets

Create wallets and control how they can be used. Start with the
[wallet operations overview](/developer-sdk/wallets), then choose a guide:

- **Policies and roles:** save a [policy template](/examples/dev-portal/create-policy), choose [permissions](/developer-sdk/permissions), and [add an authority](/developer-sdk/add-roles-and-permissions).
- **Signing and approvals:** connect a [signer](/developer-sdk/signers) or require multiple approvals with [Participant Sets](/developer-sdk/participant-sets).
- **Wallet management:** configure [authorization locks](/developer-sdk/authorization-locks), [rent claimers](/developer-sdk/rent-claimers), or [guardian recovery](/developer-sdk/use-cases/guardian-recovery).
- **Custom operations:** [prepare instructions](/developer-sdk/custom-execution) that fit the role's permissions.
