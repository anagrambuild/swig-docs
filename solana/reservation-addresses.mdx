## Introduction

Counterfactual creation derives a wallet address from its owner before the wallet is activated on-chain.

- **Use when:** you need a deposit address before asking a payer to create the wallet.
- **For:** onboarding flows and apps that activate wallets only when they are needed.

## How it works

1. Create a reservation from the program ID, owner public key, and account index or salt.
2. Derive the config and wallet addresses locally; this requires no RPC or signature.
3. Build an activation instruction from the same reservation.
4. Have a funded payer sign and submit activation. The committed owner becomes role `0` with `All` permission.
5. After confirmation, fetch the config and use the wallet normally.

## Reservation fields

| Field | Type | Meaning |
| --- | --- | --- |
| `programId` | Address | Swig deployment that will activate the wallet |
| `authorityType` | Authority type | Direct Ed25519, Secp256r1, or Secp256k1 owner |
| `publicKey` | Bytes | Owner's public key; an Ethereum address is insufficient |
| `accountIndex` | Integer | Select another wallet for the owner; defaults to `0` |
| Custom salt | 32 bytes | Alternative to an account index |

The same reservation derives the same addresses across SDK languages. Confirm that the target deployment supports reserved creation before funding an address.

## Flow

```text
Owner + index / salt
   ↓
Reserved addresses
├─ Config: read roles
└─ Wallet: receive funds
   ↓
Payer activates
   ↓
Owner uses wallet
```

## SDK example

### Reserve and prepare activation

Use the packages from [Overview](/solana#sdk-example). The Rust example also needs `solana-sdk@4` and `solana-compute-budget-interface@3` for compatible instruction types.

<Tabs>
<Tab title="TypeScript">

```typescript
import { ComputeBudgetProgram, type PublicKey } from "@solana/web3.js";
import {
  AuthorityType,
  getCreateReservedSwigInstruction,
  ReservationV1,
  SWIG_PROGRAM_ADDRESS_STRING,
} from "@swig-wallet/classic";

export async function reserveAndPrepareActivation(
  ownerPublicKey: PublicKey,
  payer: PublicKey,
) {
  const reservation = ReservationV1.create({
    programId: SWIG_PROGRAM_ADDRESS_STRING,
    authorityType: AuthorityType.Ed25519,
    publicKey: ownerPublicKey.toBytes(),
    addressOptions: { accountIndex: 0 },
  });
  const addresses = await reservation.addresses();
  const instructions = [
    ComputeBudgetProgram.setComputeUnitLimit({ units: 600_000 }),
    await getCreateReservedSwigInstruction({ reservation, payer }),
  ];

  return {
    reservation,
    configAddress: addresses.swigAddress,
    walletAddress: addresses.walletAddress,
    instructions,
  };
}
```

- `configAddress` is for fetching roles; `walletAddress` is for SOL deposits and token-account ownership.
- Send the returned instructions with the payer using [Sending transactions](/solana/transactions/sending).
- The compute limit accommodates P-256 owners. The payer pays account funding and fees; only the payer signs activation.

</Tab>
<Tab title="Rust">

```rust
use solana_compute_budget_interface::ComputeBudgetInstruction;
use solana_sdk::{instruction::Instruction, pubkey::Pubkey};
use swig_sdk::{
    authority::AuthorityType,
    reservation::{ReservationAddressOptions, ReservationError, ReservationV1},
};

pub fn reserve_wallet(owner: Pubkey) -> Result<ReservationV1, ReservationError> {
    ReservationV1::new(
        swig_interface::program_id(),
        AuthorityType::Ed25519,
        owner.as_ref(),
        ReservationAddressOptions::AccountIndex(0),
    )
}

pub fn prepare_activation(
    reservation: &ReservationV1,
    payer: Pubkey,
) -> Result<Vec<Instruction>, ReservationError> {
    let (instruction, _) = reservation.create_instruction(payer)?;
    Ok(vec![
        ComputeBudgetInstruction::set_compute_unit_limit(600_000),
        instruction,
    ])
}
```

Call `reservation.addresses()?` for `swig_address` and `wallet_address`. Sign and submit the prepared instructions with the payer.

### Restore a saved reservation

Save the reservation bytes together with a trusted wallet address. Check that restoring them still produces that address before requesting activation.

<Tabs>
<Tab title="TypeScript">

Save `reservation.toBytes()` and `walletAddress.toBase58()` from the example above.

```typescript
import {
  ReservationV1,
  SWIG_PROGRAM_ADDRESS_STRING,
} from "@swig-wallet/classic";

export async function loadReservation(
  packageBytes: Uint8Array,
  expectedWalletAddress: string,
): Promise<ReservationV1> {
  const reservation = ReservationV1.fromBytes(
    packageBytes,
    SWIG_PROGRAM_ADDRESS_STRING,
  );
  const addresses = await reservation.addresses();
  if (addresses.walletAddress.toBase58() !== expectedWalletAddress) {
    throw new Error("Restored wallet address differs from the trusted record");
  }
  return reservation;
}
```

</Tab>
<Tab title="Rust">

Save `reservation.package_bytes` and `reservation.addresses()?.wallet_address`.

```rust
use solana_sdk::pubkey::Pubkey;
use swig_sdk::reservation::ReservationV1;

pub fn load_reservation(
    package_bytes: &[u8],
    expected_wallet: Pubkey,
) -> Result<ReservationV1, Box<dyn std::error::Error>> {
    let reservation =
        ReservationV1::from_bytes(package_bytes, swig_interface::program_id())?;
    if reservation.addresses()?.wallet_address != expected_wallet {
        return Err("restored wallet differs from the trusted record".into());
    }
    Ok(reservation)
}
```

### After activation

- SOL deposited before activation remains in the wallet.
- Repeating activation does not reset an already active wallet's roles or permissions.
- Keep the original reservation after owner rotation; current roles determine who can act.
- A closed wallet cannot be recreated from its reservation.
- Reserved wallets use V2 subaccounts. Use Rust's V2 APIs for that flow; Classic's legacy V1 helpers are incompatible.
