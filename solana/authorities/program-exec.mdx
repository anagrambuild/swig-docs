---
title: "ProgramExec"
description: "Use an existing Solana program's approval to authorize a wallet operation."
---

Use ProgramExec when an existing approval or policy program authorizes wallet
operations. Configure a role with that program's ID and authorization
instruction prefix, then include its approval instruction when using the role.
The role's permissions still limit what the wallet can do.

## Register the authority

Obtain the program ID and exact authorization prefix from the integration
you are using. The prefix must fit within 40 bytes.

```typescript
import { type PublicKey } from "@solana/web3.js";
import { createProgramExecAuthorityInfo } from "@swig-wallet/classic";

function programAuthority(programId: PublicKey, authorizationPrefix: Uint8Array) {
  if (authorizationPrefix.length === 0 || authorizationPrefix.length > 40) {
    throw new Error("Use the integration's authorization prefix (1–40 bytes)");
  }
  return createProgramExecAuthorityInfo(programId.toBytes(), authorizationPrefix);
}
```

Pass the result to [add a role](/solana/add-role), with permissions scoped to
the integration. An arbitrary program call is not an approval: use an
integration whose approval binds the intended wallet operation.

## Execute an approved operation

The approval program's client supplies `approvalInstruction` for the exact
operation. For a wallet transaction, its first two accounts must be the Swig
config and wallet addresses, in that order.

```typescript
import { type PublicKey, type TransactionInstruction } from "@solana/web3.js";
import { getSignInstructions, type Swig } from "@swig-wallet/classic";

async function prepareApprovedOperation(
  swig: Swig,
  roleId: number,
  payer: PublicKey,
  approvalInstruction: TransactionInstruction,
  walletInstructions: TransactionInstruction[],
) {
  return getSignInstructions(swig, roleId, walletInstructions, false, {
    payer,
    preInstructions: [approvalInstruction],
  });
}
```

The TypeScript builder accepts exactly one approval instruction in
`preInstructions` and includes it in the returned list. Send that list once,
in order, with the payer and any additional signers required by the approval
program. See [Sending transactions](/solana/transactions/sending).

Use the integration's own instructions for operations other than transaction
execution; their approval account requirements can differ. A
[ProgramExec session](/solana/authorities/sessions) lets the program authorize
a temporary application key instead.
