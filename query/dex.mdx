## Introduction

This dataset records DEX transactions executed by a Swig wallet, including each
trade, liquidity change, fee claim, and reward claim. Use it for activity feeds,
trade history, or explaining which venues a wallet used.

The example lists transaction history with `swig.dex.transactions.list` in
TypeScript or Python. The same client provides
[one-transaction lookups and latest liquidity positions](/developer-sdk/dex-activity#read-one-transaction).
Current transaction coverage includes PumpSwap, Meteora DLMM, Raydium AMM v4,
Raydium CPMM, Raydium CLMM, and Orca Whirlpool. Latest position state covers
Raydium CLMM.

This is indexed data, so an unprocessed transaction can be absent. The API key's
organization must own the active Swig. Each admitted call or page consumes
**one DEX query**; retries and admitted errors count too. This is separate from
API-request usage. See [pricing and quotas](/query#dex-queries).

## Returned result

TypeScript field names are shown below. Python exposes the same structure with
snake_case attributes. The SDK normalizes protocol and action names.

| Field | Type | Meaning |
| :--- | :--- | :--- |
| `transactions` | array | Matching transactions, newest first |
| `transactions[].swigConfigAddress` | string | Wallet configuration account |
| `transactions[].transactionSignature` | string | Solana transaction signature |
| `transactions[].slot` | number | Transaction slot |
| `transactions[].blockTime` | string, optional | RFC 3339 block time, when known |
| `transactions[].actions` | array | Every indexed DEX action the Swig executed in that transaction |
| `actions[].actionIndex` | number | Action's order within the transaction |
| `actions[].swigVaultAddress` | string | Wallet vault or sub-account that executed the action |
| `actions[].actingRoleId` | number | Role that authorized the action |
| `actions[].protocol` | string | Normalized venue name, such as `raydium-clmm` |
| `actions[].dexProgramAddress` | string | Venue program address |
| `actions[].action` | discriminated object | Action data selected by its `type`; the example below is a swap |
| `action.protocolInstruction` | string | Venue instruction name |
| `action.protocolActorAddress` | string | Account whose asset changes the action describes |
| `action.dexPoolAddress` | string | Pool address for a swap |
| `action.input`, `action.output` | object | Mint address, signed decimal-string `amountRaw`, and optional `decimals` |
| `nextCursor` | object, optional | Last row's `slot` and `transactionSignature`; absent on the final page |

An action's negative amount left its protocol actor; a positive amount entered
it. When an aggregator holds the assets, that actor can be the router rather
than the Swig vault. Keep raw amounts as strings or arbitrary-precision integers.
Other action types carry deposits, withdrawals, or claims; see
[DEX action fields](/developer-sdk/dex-activity#what-a-transaction-carries).

## Input parameters

Use the [server client](/developer-sdk/integration-paths) as `swig`.

| TypeScript / Python | Required | Description |
| :--- | :--- | :--- |
| `swigConfigAddress` / `swig_config_address` | Yes | Swig config address owned by your organization |
| `network` | No | `mainnet` or `devnet`; otherwise use the client's setting |
| `pageSize` / `page_size` | No | 25 by default; maximum 100 |
| `cursor` | No | Previous response's `nextCursor` / `next_cursor` |
| `startSlot`, `endSlot` / `start_slot`, `end_slot` | No | Inclusive slot range; start must not exceed end |
| `protocol` | No | One of the supported normalized venue names |
| `actionType` / `action_type` | No | `swap`, `position-open`, `liquidity-add`, `liquidity-remove`, `position-rebalance`, `fee-claim`, `reward-claim`, or `position-close` |
| `swigVaultAddress` / `swig_vault_address` | No | Restrict to a vault or sub-account |

Filters combine with AND. Protocol, action type, and vault must match the same
action; each returned transaction still includes all its indexed DEX actions.
Pass the cursor unchanged with the same wallet, network, and filters.

## SDK example

<CodeGroup>
```typescript TypeScript
const result = await swig.dex.transactions.list({
  swigConfigAddress,
  network: 'mainnet',
  pageSize: 25,
  protocol: 'raydium-clmm',
  actionType: 'swap',
});
```

```python Python
result = await swig.dex.transactions.list(
    swig_config_address=swig_config_address,
    network="mainnet",
    page_size=25,
    protocol="raydium-clmm",
    action_type="swap",
)
```
</CodeGroup>
