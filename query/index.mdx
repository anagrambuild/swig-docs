## Pricing and included usage

These are the standard Swig subscription plans. Query access uses your existing
organization subscription.

| Plan | Monthly price (USD) | Included API requests | DEX queries per calendar month | API-request overage |
| :--- | ---: | ---: | ---: | :--- |
| Free | $0 | 50,000 | 10,000 | Hard cap; upgrade to continue |
| Pro | $39 | 100,000 | 2,000,000 | $2.50 per 1,000 additional requests |
| Ultra | $399 | 250,000 | 10,000,000 | $2.25 per 1,000 additional requests |
| Enterprise | Custom | 500,000+ | 10,000,000 | From $2.00 per 1,000 additional requests |

Enterprise API-request allowances and pricing depend on your agreement. The DEX
query cap is separate. Check your organization's plan and billing period in the
[Developer Portal](https://dashboard.onswig.com); see
[subscription management](/examples/dev-portal/subscriptions-billing) to change plans.

### API requests

- Wallet, yield, ramp, rent-recipient, and paymaster queries each consume one API
  request. Paginated queries consume one request per page.
- This allowance is shared with other metered API operations, such as transaction
  preparation and sponsorship, and attributed IdP requests. It is not reserved
  for queries.
- Free organizations stop at 50,000 requests in a UTC calendar month. Paid plans
  continue beyond their included requests with the API-request overage above.
- Subscription invoices follow your billing period. The Free admission cap
  resets at 00:00 UTC on the first day of each calendar month.

### DEX queries

- Each DEX transaction-list, transaction-detail, or position-list call consumes
  one DEX query and does not consume the API-request allowance.
- The quota is shared by the organization's API keys and networks. It resets
  at 00:00 UTC on the first day of each calendar month.
- Every plan has a hard DEX cap. At the cap, requests return HTTP `429`
  (`RESOURCE_EXHAUSTED`); API-request overage does not buy more DEX queries.
- Use a plan with a larger quota or wait for the next calendar month. Contact
  Swig if your required volume exceeds the published plans.

### What counts

Usage is counted when an authenticated request is admitted, before the operation
finishes. Retries, empty results, and admitted requests that later return errors
such as `400` or `404` still count. A rejected API key or exhausted quota does
not add an admitted request. Each returned row is not a separate charge.

For example, querying token balances once and three pages of DEX history uses
**one API request and three DEX queries**. Retrying one DEX page adds one DEX query.

| Section | Available data | Usage allowance |
| :--- | :--- | :--- |

## Make your first query

[Create an API key](/examples/dev-portal/create-api-key) and initialize the server
client using [Client setup](/developer-sdk/integration-paths). Choose the guide
above for its inputs, returned fields, and pagination rules.

<CodeGroup>
```typescript TypeScript
const wallet = swig.wallets.use(swigConfigAddress);
const result = await wallet.listTokenBalances();
```

```python Python
wallet = swig.wallets.use(swig_config_address)
result = await wallet.list_token_balances()
```

```rust Rust
let result = wallet.list_token_balances(&swig_config_address).await?;
```
</CodeGroup>

This call consumes one API request. Indexed data can lag chain state; each guide
explains its freshness signals. Track transaction confirmation separately.

## Errors

| Error | Meaning |
| :--- | :--- |
| API admission cap | Free usage reached its UTC calendar-month allowance; paid API overage follows the plan. |
| 429 / RESOURCE_EXHAUSTED | The separate monthly DEX query cap is exhausted. API overage does not extend it. |
| Authentication rejected | The request is not admitted and does not add usage. |
