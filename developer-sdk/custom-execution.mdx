## Introduction

A custom transaction executes your Solana instructions through an existing Swig
wallet. Use it to integrate a program that the transfer and swap helpers do not
cover. The acting role's program and asset permissions still apply.

The backend prepares the transaction; your application reviews, signs, and
submits it. Use the [Protocol SDK](/products-and-sdks) for direct instruction construction.

## Input

| Parameter | Required | Description |
| :--- | :--- | :--- |
| Wallet config address and network | Yes | Bind through the configured wallet client |
| Requester authority | Yes | Ed25519, secp256r1, or ParticipantSet authority |
| `feePayer` / `fee_payer` | Yes | Public key paying the transaction fee |
| `instructions` | Yes | Nonempty ordered list of program IDs, account metadata, and instruction data |
| Account metadata | For each instruction | Public key and signer/writable flags |
| `addressLookupTableAccounts` / `address_lookup_table_accounts` | No | Distinct lookup-table addresses; must be empty for ParticipantSet requests |

A signer account must be the derived Swig wallet address, fee payer, or
Ed25519 requester. TypeScript accepts base64 instruction data; Python and Rust
examples use bytes. Rust uses native `Instruction` and `AccountMeta` values.

## SDK example

Use a wallet handle with its requester authority in TypeScript/Python, or
`WalletClient` in Rust. See [Client setup](/developer-sdk/integration-paths).

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.buildTransaction({
  feePayer,
  instructions: [
    {
      programId: targetProgramId,
      accounts: [
        {
          pubkey: writableAccount,
          isWritable: true,
        },
        {
          pubkey: readonlyAccount,
        },
      ],
      data: Buffer.from(instructionData).toString('base64'),
    },
  ],
  addressLookupTableAccounts: [lookupTableAddress],
});
```

```python Python
from swig_developer_sdk import SolanaAccountMeta, SolanaInstructionInput

prepared = await wallet.build_transaction(
    fee_payer=fee_payer,
    instructions=(
        SolanaInstructionInput(
            program_id=target_program_id,
            accounts=(
                SolanaAccountMeta(
                    pubkey=writable_account,
                    is_writable=True,
                ),
                SolanaAccountMeta(pubkey=readonly_account),
            ),
            data=instruction_data,
        ),
    ),
    address_lookup_table_accounts=(lookup_table_address,),
)
```

```rust Rust
use swig_developer_sdk::{AccountMeta, Instruction, PrepareTransactionArgs};

let prepared = wallet
    .prepare_transaction(PrepareTransactionArgs {
        swig_config_address,
        fee_payer,
        requester_authority: requester_authority.clone(),
        instructions: vec![Instruction {
            program_id: target_program_id,
            accounts: vec![
                AccountMeta::new(writable_account, false),
                AccountMeta::new_readonly(readonly_account, false),
            ],
            data: instruction_data,
        }],
        address_lookup_table_accounts: vec![lookup_table_address],
    })
    .await?;
```

</CodeGroup>

Review the returned transaction and complete [Signing](/developer-sdk/signers).
ParticipantSet operations first need [approval compilation](/developer-sdk/participant-sets).
An empty embedded-signature list does not remove native Ed25519 signer requirements.
