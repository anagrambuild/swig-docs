## Introduction

An authorization lock reserves an asset amount for a role until it is spent,
released, or expires. Use it when an authorized operation needs a temporary hold
on SOL or tokens while other roles continue using the wallet.

The backend prepares unsigned transactions. Your application handles approval,
signing, and submission. Hosted support remains under review in
[TypeScript/Python PR #66](https://github.com/anagrambuild/swig-developer-sdk/pull/66)
and [Rust PR #79](https://github.com/anagrambuild/swig-developer-sdk/pull/79), and
requires matching backend routes and the authorization-lock program.

## SDK examples

### Choose the wallet

These examples target the unpublished SDK changes linked above. Use a configured client and the role that will hold or release the lock.

<CodeGroup>

```typescript TypeScript
const wallet = swig.wallets.use(swigConfigAddress, {
  requesterAuthority: { ed25519: { publicKey: requesterPublicKey } },
});
```

```python Python
wallet = swig.wallets.use(
    swig_config_address,
    requester_authority={"ed25519": {"public_key": requester_public_key}},
)
```

</CodeGroup>

### Reserve SOL

Prepare a temporary lamport hold for the acting role.

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.addAuthorizationLock({
  feePayer, amount: '1000000', durationSlots: 150,
});
```

```python Python
prepared = await wallet.add_authorization_lock(
    fee_payer=fee_payer, amount=1_000_000, duration_slots=150,
)
```

```rust Rust
use swig_developer_sdk::{AuthorizationLockExpiry, PrepareAddAuthorizationLockArgs};

let prepared = wallet.prepare_add_authorization_lock(PrepareAddAuthorizationLockArgs {
    swig_config_address, fee_payer,
    requester_authority: requester_authority.clone(),
    mint: None, amount: 1_000_000,
    expiry: AuthorizationLockExpiry::DurationSlots(150),
}).await?;
```

</CodeGroup>

### Reserve a token

Choose a mint to reserve base units in the wallet’s associated token account. An absolute expiry is an alternative to a relative duration.

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.addAuthorizationLock({
  feePayer, mint, amount: '10000000', expirySlot,
});
```

```python Python
prepared = await wallet.add_authorization_lock(
    fee_payer=fee_payer, mint=mint, amount=10_000_000, expiry_slot=expiry_slot,
)
```

```rust Rust
let prepared = wallet.prepare_add_authorization_lock(PrepareAddAuthorizationLockArgs {
    swig_config_address, fee_payer,
    requester_authority: requester_authority.clone(),
    mint: Some(mint), amount: 10_000_000,
    expiry: AuthorizationLockExpiry::ExpirySlot(expiry_slot),
}).await?;
```

</CodeGroup>

### List holds

Inspect remaining amounts after confirmation. Include inactive records when you need to reconcile or prune them.

<CodeGroup>

```typescript TypeScript
const holds = await wallet.getAuthorizationLocks({ includeExpired: true });
```

```python Python
holds = await wallet.get_authorization_locks(include_expired=True)
```

```rust Rust
let holds = wallet.get_authorization_locks(&swig_config_address, true).await?;
```

</CodeGroup>

### Release or prune a hold

The holder releases its active hold. Eligible managing roles may prune expired or fully captured records.

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.removeAuthorizationLock({ feePayer, lockId });
```

```python Python
prepared = await wallet.remove_authorization_lock(fee_payer=fee_payer, lock_id=lock_id)
```

```rust Rust
use swig_developer_sdk::PrepareRemoveAuthorizationLockArgs;

let prepared = wallet.prepare_remove_authorization_lock(PrepareRemoveAuthorizationLockArgs {
    swig_config_address, fee_payer, requester_authority, lock_id,
}).await?;
```

</CodeGroup>

Add/remove calls return unsigned transactions. Complete participant approval when required, then [sign](/developer-sdk/signers), submit, and confirm before querying again.

## Input

| Operation | Parameter | Description |
| :--- | :--- | :--- |
| All | Wallet config and network | Existing wallet on the configured client |
| Read | `includeExpired` / `include_expired` | Include expired and fully captured records |
| Add/remove | Requester and fee payer | Authority for the operation and public fee-payer key |
| Add | `amount` | Lamports or token base units; use an exact integer value |
| Add | `mint` | Omit for SOL; supply a mint to hold tokens in the wallet's associated token account |
| Add | `durationSlots` / `duration_slots` or `expirySlot` / `expiry_slot` | Choose exactly one; the role's maximum duration still applies |
| Remove | `lockId` / `lock_id` | ID of the hold to release or prune |

The acting role needs `ManageAuthorizationLocks { max_duration_slots }`, even
with `All`, and a limited role also needs the asset's spending permission.
Grant this through the [Protocol SDK](/protocol/authorization-locks); the hosted
add-role API does not expose it. A delegated role cannot raise its own duration bound.

Only the holder can release an active hold. The holder or an eligible managing
role can prune expired or fully captured records. Normal spending by the holder
captures the hold and reduces its remaining amount; zero is valid.

TypeScript accepts exact decimal strings or bigint for large values. Python validates amounts/slots as unsigned 64-bit integers and lock IDs as unsigned 32-bit integers. Rust uses `u64` amounts/slots, `u32` IDs, and native addresses.

## Output

| Read field | Meaning |
| :--- | :--- |
| `currentSlot` / `current_slot` | Slot used to evaluate the returned holds |
| `nextLockId` / `next_lock_id` | Next lock identifier |
| `locks[].lockId` / `lock_id` | Hold identifier |
| `locks[].roleId` / `role_id` | Holder role |
| `locks[].assetAccount` / `asset_account` | Account containing the reserved asset |
| `locks[].mint` | Token mint; absent for native SOL |
| `locks[].amount` | Remaining base-unit amount as an exact decimal string |
| `locks[].expirySlot` / `expiry_slot` | Expiry slot as an exact decimal string |
| `locks[].active` | True while unexpired with a nonzero remaining amount |

## Errors

| Error | Meaning |
| :--- | :--- |
| Missing lock-management permission | The requester lacks ManageAuthorizationLocks, even if it has All. Grant the scoped permission through a compatible Protocol SDK integration. |
| Invalid amount or expiry | An integer is out of range, expiry is ambiguous, or duration exceeds the role bound. Use exact base units and exactly one permitted duration or expiry slot. |
| Active hold cannot be released | The requester is not the holder of that active lock. Use the holder role; eligible managing roles may prune inactive records. |
| Hosted method unavailable | The installed SDK/backend does not include the linked lock changes. Use matching supported builds or the Protocol SDK recipe. |
