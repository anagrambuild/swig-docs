## Introduction

x402 lets a Swig wallet pay for an HTTP resource that returns `402 Payment
Required`. Use it for paid APIs and services whose facilitator supports Swig
smart-wallet verification. The SDK prepares the payment; the resource provider’s
facilitator verifies and settles it after the paid retry.

Use the configured clients from [Client setup](/developer-sdk/integration-paths).
`signTransaction` / `sign_transaction` is your application’s signing callback.
Approve the exact recipient, mint, amount, and network before signing.

## SDK examples

### Pay for a resource

This GET example preserves the resource URL and sends a payment header after signing. Keep the original method, body, and headers for other request types.

<CodeGroup>

```typescript TypeScript
import {
  createX402Payment,
} from '@swig-wallet/developer-sdk';
import { signPreparedTransaction } from '@swig-wallet/developer-sdk/signers';

const wallet = swig.wallets.use({
  swigConfigAddress,
  walletAddress,
  requesterAuthority: {
    ed25519: { publicKey: developerPublicKey },
  },
});

const challenge = await fetch(resourceUrl, { redirect: 'manual' });
const prepared = await wallet.x402.prepareFromResponse(challenge);

const signed = await signPreparedTransaction(
  prepared.preparedTransaction,
  { signTransaction },
);

const payment = createX402Payment(prepared, signed);

const paidResponse = await fetch(resourceUrl, {
  headers: payment.paymentSignatureHeaders,
  redirect: 'manual',
});

if (!paidResponse.ok) {
  throw new Error(`Paid request failed: ${paidResponse.status}`);
}

const resource = await paidResponse.json();
const paymentResponse = paidResponse.headers.get('PAYMENT-RESPONSE');
```

```python Python
import asyncio

import httpx

from swig_developer_sdk import create_x402_payment
from swig_developer_sdk.signers import sign_prepared_transaction

wallet = swig.wallets.use(
    swig_config_address,
    requester_authority={
        "ed25519": {"publicKey": developer_public_key},
    },
)

async def main() -> None:
    async with httpx.AsyncClient(follow_redirects=False) as http:
        challenge = await http.get(resource_url)
        prepared = await wallet.x402.prepare_from_response(challenge)

        signed = await sign_prepared_transaction(
            prepared.prepared_transaction,
            sign_transaction=sign_transaction,
        )

        payment = create_x402_payment(prepared, signed)

        paid_response = await http.get(
            resource_url,
            headers=payment.payment_signature_headers,
        )
        paid_response.raise_for_status()

        resource = paid_response.json()
        payment_response = paid_response.headers.get("PAYMENT-RESPONSE")


if __name__ == "__main__":
    asyncio.run(main())
```

```rust Rust
use reqwest::Client;
use swig_developer_sdk::{
    x402::{create_x402_payment, parse_payment_required},
    PrepareX402PaymentArgs, WalletAuthority,
};

let http = Client::builder()
    .redirect(reqwest::redirect::Policy::none())
    .build()?;

let challenge = http.get(&resource_url).send().await?;
if challenge.status().is_redirection() {
    return Err("resource redirect requires a new payment flow".into());
}
let payment_required = parse_payment_required(challenge.status(), challenge.headers())?;

let prepared = wallet
    .prepare_x402_payment(PrepareX402PaymentArgs {
        swig_config_address,
        requester_authority: WalletAuthority::Ed25519 {
            public_key: requester_public_key,
        },
        payment_required,
        accepted_index: None,
    })
    .await?;

let signed_transaction = sign_transaction(&prepared.prepared_transaction).await?;

let payment = create_x402_payment(
    prepared.payment_required,
    prepared.accepted_index,
    signed_transaction,
)?;
let response = http
    .get(&resource_url)
    .headers(payment.payment_signature_headers)
    .send()
    .await?;
if response.status().is_redirection() {
    return Err("resource redirected after payment submission".into());
}
let paid_response = response.error_for_status()?;
```

</CodeGroup>

### Choose a payment offer

Select an explicit zero-based offer index when the customer has approved that offer. Omit it to select the first supported offer on the wallet’s network.

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.x402.prepareFromResponse(challenge, {
  acceptedIndex: 2,
});
```

```python Python
prepared = await wallet.x402.prepare_from_response(
    challenge,
    accepted_index=2,
)
```

```rust Rust
use swig_developer_sdk::{PrepareX402PaymentArgs, WalletAuthority};

let prepared = wallet
    .prepare_x402_payment(PrepareX402PaymentArgs {
        swig_config_address,
        requester_authority: WalletAuthority::Ed25519 {
            public_key: requester_public_key,
        },
        payment_required,
        accepted_index: Some(2),
    })
    .await?;
```

## Flow

```text
Request resource
  └─ Receive 402 challenge
      └─ Approve and sign
          └─ Paid retry
              └─ Settle
```

## Input

| Input | Requirement |
| :--- | :--- |
| Wallet and requester | Existing wallet with an Ed25519 or secp256r1 role allowed to invoke the token program and spend the mint. |
| Challenge | x402 version 2 with the `exact` scheme on the wallet’s Solana mainnet/devnet network. Preserve the original `accepts` indexes. |
| `acceptedIndex` / `accepted_index` | Optional index of the approved offer. An incompatible explicit choice errors rather than silently selecting another. |
| Token accounts | Already-created canonical ATAs for the wallet and recipient. Wallet ATA must hold enough tokens. |
| Token support | Legacy SPL Token or Token-2022 mint without extensions; token-account extensions may be absent or only `ImmutableOwner`. |
| Fee payer | Use the offer’s fee payer, different from the requester. Leave its signature empty for facilitator settlement; sign only application-owned slots. |
| Facilitator | Must support Swig verification; passkey payments also require its support for the secp256r1 verification program. |
| Paid request | Original request plus `PAYMENT-SIGNATURE`. Disable redirects so payment headers are not forwarded to another destination. |

## Output

`prepareFromResponse()` / `prepare_from_response()` returns these fields.
Rust's `prepare_x402_payment` returns them as `X402PaymentPreparation`:

| Field | Description |
| :--- | :--- |
| `preparedTransaction` / `prepared_transaction` | The unsigned Swig payment transaction and any embedded signature requests |
| `paymentRequired` / `payment_required` | The validated x402 payment challenge used during preparation |
| `acceptedIndex` / `accepted_index` | The selected offer's position in the original `accepts` array |

Rust's `prepare_x402_payment` sends its POST once. This flow does not use the Swig paymaster.

After signing, `createX402Payment()` / `create_x402_payment()` returns:

| Field | Description |
| :--- | :--- |
| `paymentPayload` / `payment_payload` | The x402 payment payload containing the selected offer and signed transaction |
| `paymentSignatureHeaders` / `payment_signature_headers` | A `PAYMENT-SIGNATURE` header ready to merge into the resource retry |

Rust's `create_x402_payment` checks the selected offer, transaction structure,
and encoded size limits (1,232 transaction bytes and 8,000 header bytes). It
does not verify signatures or transaction intent. The facilitator verifies and
settles the payment when the paid request reaches the resource provider.

## Errors

| Error | Meaning |
| :--- | :--- |
| Invalid payment challenge | Expected HTTP 402 and a valid `PAYMENT-REQUIRED` header with supported version/scheme/network. |
| Unsupported selected offer | The explicit index is out of range or names an incompatible offer. |
| Account, permission, or token failure | Missing/unfunded ATA, unsupported Token-2022 extension, or insufficient role permission. |
| Invalid signed payload | Transaction structure or encoded size is invalid. Rust limits transactions to 1,232 bytes and payment headers to 8,000 bytes. |
| Failed or missing paid response | Settlement may already have happened. Reconcile with the resource service before paying again; the SDK does not reconcile automatically. |
| Redirect | A different destination needs fresh approval and a new challenge. Preserve the previous payment outcome; do not forward its header. |
