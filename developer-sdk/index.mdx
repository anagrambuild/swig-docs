---
title: "Developer SDK Overview"
---

The Swig Developer SDK is the hosted, API-key-based SDK surface for preparing wallet operations on a server and signing only the required transactions on the client.

It lives in `swig-ts/packages/developer-sdk` and ships as `@swig-wallet/developer-sdk`.

## Access model

This SDK requires developer-portal access.

In practice that means:

1. Sign up through the Swig developer portal
2. Create an API key
3. Use that API key on your server
4. Return prepared transactions to the client for signing

## Core model

The SDK is prepare-first.

### Typical flow

1. Your server creates a `SwigClient` with an API key
2. The server prepares a wallet operation
3. The backend returns one or more unsigned transactions
4. The client signs the transactions that require client authority
5. The app submits them directly or through a sponsor flow

## Package surface

The package exposes multiple entry points for different runtime roles:

- `@swig-wallet/developer-sdk/server/typescript` for server-side TypeScript control
- `@swig-wallet/developer-sdk/client` for client-side signing helpers
- `@swig-wallet/developer-sdk/browser` for browser-side wallet handles
- `@swig-wallet/developer-sdk/next` for Next.js route helpers
- `@swig-wallet/developer-sdk/nest` for NestJS route helpers

## What it is good for

- API-key-backed wallet creation
- server-side preparation of transfers and swaps
- keeping backend credentials out of the browser
- controlled client signing flows
- building app-specific proxy routes around Swig transactions

## What it is not

This is not the same thing as the direct protocol SDKs in `@swig-wallet/classic`, `@swig-wallet/kit`, or `swig-sdk`.

Those SDKs integrate with the protocol directly.

This SDK integrates with hosted Swig backend services and depends on developer-portal provisioning.
