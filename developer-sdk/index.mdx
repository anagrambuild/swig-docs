The Swig Developer SDK is a server-side toolkit for TypeScript and Python.
It authenticates to Swig's hosted API, prepares wallet operations as unsigned
transactions, reads wallet state, and submits transactions your application
has signed.

## Install

<Tabs>

<Tab title="TypeScript">

```bash
bun add @swig-wallet/developer-sdk
```

Published package `@swig-wallet/developer-sdk`, version `0.10.0`, includes
general role creation and ParticipantSet support.

</Tab>

<Tab title="Python">

```bash
pip install swig-developer-sdk
```

Published package `swig-developer-sdk`, version `0.9.0`, includes general role
creation and ParticipantSet support. Requires Python 3.10 or later.

</Tab>

</Tabs>

Both packages live in
[anagrambuild/swig-developer-sdk](https://github.com/anagrambuild/swig-developer-sdk)
and default to `https://api.onswig.com`.

## What the SDK owns

- API-key authentication and retry behavior
- wallet creation and unsigned transaction preparation
- transfers, swaps, grouped operations, and custom instructions
- threshold ParticipantSet creation, role assignment, and approval compilation
- wallet, role, paymaster, and ramp reads
- fiat on-ramp and off-ramp server operations
- sponsorship of application-signed transactions and mainnet bundles
- optional signing helpers that combine application-provided signatures with
  prepared transactions

## What your application owns

- end-user authentication and authorization
- frontend transport and user interfaces
- wallet-provider, passkey, hardware-wallet, or custody integration
- every private key and user authorization decision
- confirmation and finality tracking after submission

The server SDK returns unsigned prepared transactions and signature-request
metadata. Your application obtains the signature. The optional signing helpers
can assemble that signature into the prepared transaction without receiving an
API key or private key.

## Choose the matching Swig product

- Use this SDK when a trusted server should call Swig's hosted API.
- Use the [Developer API](/developer-api) for direct REST integration.
- Use the [Protocol SDK](/reference) when your application integrates directly
  with the on-chain protocol and owns the full transaction lifecycle.
- Use the [IDP SDK](/idp-sdk) for browser or mobile authentication flows.

## Set up your integration

Start with an SDK language and an API key for your trusted server. Then choose
what each wallet role may do and how its authority will sign. An API key
authenticates hosted API requests; wallet operations still require the
appropriate authority's signature or approval proofs.

## Configure wallet access

Use [Policy Templates](/examples/dev-portal/create-policy) to save wallet-creation
configuration and [Read Policy Templates](/examples/dev-portal/fetch-policy) to inspect
it. For an existing wallet, use [Add Roles](/developer-sdk/add-roles-and-permissions)
to attach an authority and its permissions. [Signers](/developer-sdk/signers)
explains application-owned signing; [Participant Sets](/developer-sdk/participant-sets)
extends one role to require M-of-N approvals.

<Note>
  Guardian recovery requires additional protocol and SDK integration.
  See [Guardian recovery](/developer-sdk/permissions#guardian-recovery) for
  scoped key replacement, the proposed multiple-approval extension, and
  current support boundaries.
</Note>
