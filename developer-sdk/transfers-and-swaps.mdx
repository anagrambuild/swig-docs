Prepare wallet movements from a trusted server. The SDK returns unsigned
transactions; signing stays in application-owned wallet or custody code.

## Start from a wallet handle

<CodeGroup>

```typescript TypeScript
const wallet = swig.wallets.use({
  swigConfigAddress,
  walletAddress,
  requesterAuthority: {
    ed25519: { publicKey: authorityPublicKey },
  },
});
```

```python Python
from swig_developer_sdk import WalletReference

wallet = swig.wallets.use(
    WalletReference(
        swig_config_address=swig_config_address,
        wallet_address=wallet_address,
        requester_authority={
            "ed25519": {"publicKey": authority_public_key},
        },
    )
)
```

</CodeGroup>

TypeScript and Python authority shapes may also be `secp256k1` or
`secp256r1`. The SDK uses the public authority value to prepare the correct
request; it never accesses the corresponding private key or authenticator.

Rust supplies the config address and requester authority on each call. See
[Rust integration](/developer-sdk/integration-paths#rust) for client setup.
Supported requesters are Ed25519, secp256r1, and ParticipantSet.

## SOL transfer

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.transfer.sol({
  feePayer,
  destination,
  amount: 1_000_000n,
});
```

```python Python
prepared = await wallet.transfer.sol(
    fee_payer=fee_payer,
    destination=destination,
    amount=1_000_000,
)
```

```rust Rust
use swig_developer_sdk::PrepareTransferSolArgs;

let prepared = wallet
    .prepare_transfer_sol(PrepareTransferSolArgs {
        swig_config_address,
        fee_payer,
        requester_authority: requester_authority.clone(),
        destination,
        amount: 1_000_000,
    })
    .await?;
```

</CodeGroup>

Use a positive amount in lamports.

## Token transfer

Token transfers are owner-based. The backend derives the token program,
source associated token account, destination associated token account, and any
destination account creation it needs.

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.transfer.token({
  feePayer,
  mint,
  destinationOwner,
  amount: 10_000n,
});
```

```python Python
prepared = await wallet.transfer.token(
    fee_payer=fee_payer,
    mint=mint,
    destination_owner=destination_owner,
    amount=10_000,
)
```

```rust Rust
use swig_developer_sdk::PrepareTransferTokenArgs;

let prepared = wallet
    .prepare_transfer_token(PrepareTransferTokenArgs {
        swig_config_address,
        fee_payer,
        requester_authority: requester_authority.clone(),
        mint,
        destination_owner,
        amount: 10_000,
    })
    .await?;
```

</CodeGroup>

Use a positive amount in the mint's smallest units.

## Continue the flow

For threshold-authorized SOL or token transfers, follow the
[Participant Sets](/developer-sdk/participant-sets) flow for role creation,
approval collection, and compilation. A scoped SOL-transfer role carries both
System Program access and a SOL spending limit.

Use the requester authority and the serialized transaction's required signer
set to coordinate signing in your application. For `secp256r1` and
`secp256k1`, also process every `signatureRequests` / `signature_requests`
record. The optional [signing helpers](/developer-sdk/signers)
can adapt application-provided signatures. With TypeScript and Python, return
the signed base64 transaction to the server, then use
[Sponsor & Submit](/developer-sdk/sponsor-and-submit) or your own RPC path.

Keep Rust's preparation metadata until signing is complete. For a
ParticipantSet requester, collect and compile the approvals in
`participant_set_approval_plan` before submission.

For swaps and multi-operation preparation, continue to
[Swaps](/developer-sdk/swaps-and-batches).
