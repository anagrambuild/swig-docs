## Introduction

Transfer moves SOL or tokens from a Swig wallet to another account. Use it for
payments, withdrawals, or distributing funds to several recipients. The SDK
prepares transactions for the selected role; your application signs and submits
them. Use clients from [Client setup](/developer-sdk/integration-paths).

## SDK examples

### Choose the wallet

Use an existing config and the authority that will authorize the transfer.

<CodeGroup>

```typescript TypeScript
const wallet = swig.wallets.use({
  swigConfigAddress,
  walletAddress,
  requesterAuthority: {
    ed25519: { publicKey: authorityPublicKey },
  },
});
```

```python Python
from swig_developer_sdk import WalletReference

wallet = swig.wallets.use(
    WalletReference(
        swig_config_address=swig_config_address,
        wallet_address=wallet_address,
        requester_authority={
            "ed25519": {"publicKey": authority_public_key},
        },
    )
)
```

</CodeGroup>

### Transfer SOL

Send a positive amount in lamports to a Solana address.

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.transfer.sol({
  feePayer,
  destination,
  amount: 1_000_000n,
});
```

```python Python
prepared = await wallet.transfer.sol(
    fee_payer=fee_payer,
    destination=destination,
    amount=1_000_000,
)
```

```rust Rust
use swig_developer_sdk::PrepareTransferSolArgs;

let prepared = wallet
    .prepare_transfer_sol(PrepareTransferSolArgs {
        swig_config_address,
        fee_payer,
        requester_authority: requester_authority.clone(),
        destination,
        amount: 1_000_000,
    })
    .await?;
```

</CodeGroup>

### Transfer a token

Send base units to a recipient owner. The backend resolves associated token accounts and prepares destination-account creation when needed.

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.transfer.token({
  feePayer,
  mint,
  destinationOwner,
  amount: 10_000n,
});
```

```python Python
prepared = await wallet.transfer.token(
    fee_payer=fee_payer,
    mint=mint,
    destination_owner=destination_owner,
    amount=10_000,
)
```

```rust Rust
use swig_developer_sdk::PrepareTransferTokenArgs;

let prepared = wallet
    .prepare_transfer_token(PrepareTransferTokenArgs {
        swig_config_address,
        fee_payer,
        requester_authority: requester_authority.clone(),
        mint,
        destination_owner,
        amount: 10_000,
    })
    .await?;
```

</CodeGroup>

### Group transfers

Prepare an ordered plan containing multiple SOL and token transfers.

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.prepare({
  feePayer,
  operations: [
    {
      type: 'transferSol',
      destination,
      amount: 1_000_000n,
    },
    {
      type: 'transferToken',
      mint,
      destinationOwner,
      amount: 10_000n,
    },
  ],
});
```

```python Python
from swig_developer_sdk import TransferSolOperation, TransferTokenOperation

prepared = await wallet.prepare(
    fee_payer=fee_payer,
    operations=(
        TransferSolOperation(
            destination=destination,
            amount=1_000_000,
        ),
        TransferTokenOperation(
            mint=mint,
            destination_owner=destination_owner,
            amount=10_000,
        ),
    ),
)
```

```rust Rust
use swig_developer_sdk::{PrepareOperation, PrepareTransfersArgs};

let prepared = wallet
    .prepare_transfers(PrepareTransfersArgs {
        swig_config_address,
        fee_payer,
        requester_authority: requester_authority.clone(),
        operations: vec![
            PrepareOperation::TransferSol {
                destination,
                amount: 1_000_000,
            },
            PrepareOperation::TransferToken {
                mint,
                destination_owner,
                amount: 10_000,
            },
        ],
    })
    .await?;
```

</CodeGroup>

TypeScript/Python return an ordered transaction list. Sign and submit it in order. Rust accepts a response containing exactly one transaction, even when that transaction holds multiple operations.

## Input

| Operation | Input | Requirement |
| :--- | :--- | :--- |
| All | Wallet config, network, requester authority | Existing wallet and a role permitted to invoke the target program and spend the asset. Rust supplies these on each call. |
| All | `feePayer` / `fee_payer` | Public key paying fees and any destination-account rent. |
| SOL | `destination`, `amount` | Recipient public key and positive integer lamports. |
| Token | `mint`, `destinationOwner` / `destination_owner`, `amount` | Token mint, recipient owner (not an arbitrary token account), and positive base units. |
| Grouped | `operations` | Nonempty ordered list of SOL/token operations; same requester and fee payer. |

Use `bigint` or decimal strings for large TypeScript amounts, Python integers,
and Rust `u64`. Rust supports Ed25519, secp256r1, and ParticipantSet requesters.
For a participant set, [compile member approvals](/developer-sdk/participant-sets)
before signing the outer transaction. See [Signing](/developer-sdk/signers) for
embedded requests and native signer requirements.

## Errors

| Error | Meaning |
| :--- | :--- |
| Invalid amount or address | Amounts must be positive base-unit integers and addresses must match the operation’s account type. |
| Permission denied | The role lacks program access or sufficient spending allowance; both are checked. |
| Insufficient funds | The wallet cannot cover the transfer or the fee payer cannot cover fees/account rent. |
| Unsupported Rust plan | Rust rejects zero or multiple returned transactions. TypeScript/Python can consume ordered plans. |
