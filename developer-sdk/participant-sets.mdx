## Introduction

A participant set lets independent members authorize one Swig role with an
M-of-N threshold. Use it for shared control, such as requiring two members to
approve a transfer. The set determines who approves; the role's permissions
determine what they may do.

Each set belongs to one Swig config. Members can use Ed25519, secp256r1/passkeys,
or secp256k1. Approvals bind the same operation and shared nonce.

## Flow

```text
+----------------------------+
| Create set and confirm     |
+----------------------------+
              |
              v
+----------------------------+
| Add role and confirm       |
+----------------------------+
              |
              v
+----------------------------+
| Prepare one operation      |
+----------------------------+
              |
              v
+----------------------------+
| Collect member approvals   |
+----------------------------+
              |
              v
+----------------------------+
| Compile, sign, and submit  |
+----------------------------+
```

## Input

| Step | Parameter | Description |
| :--- | :--- | :--- |
| Create | Wallet config, network, fee payer | Existing wallet and public fee-payer address |
| Create | `members` | Public authorities of the selected members |
| Create | `threshold` | Number of distinct approvals required; the example uses 2 of 2 |
| Create | `setId` / `set_id` | Optional set identifier |
| Add role | Set address and `actions` | Give the set a role using an existing Ed25519 or secp256r1 administrator |
| Prepare | Set requester and operation inputs | Use the assigned role ID in Rust; retain the returned approval plan |
| Approve | Member request and matching signer | Send each member its own challenge with the operation visible |
| Compile | Original preparation and approvals | Supply distinct, valid approvals meeting the threshold |

Serialize operations per set. Concurrent plans share the next nonce; once one
lands, prepare and approve the others again.

Supported flows include SOL/token transfers, transfer batches, and custom
instructions without lookup tables. Swaps and lookup-table transactions need a
direct requester. Hosted recovery preparation is not supported.

## Errors

| Failure | Cause | What to do |
| :--- | :--- | :--- |
| Insufficient or duplicate approvals | The submitted proofs do not satisfy the threshold with distinct members. | Collect valid approvals from enough different members. |
| Stale nonce or expired plan | Another operation consumed the nonce or the approval window passed. | Prepare a new operation and collect fresh approvals. |
| Member signer mismatch | The signer type or public key differs from its request. | Send each request to its matching member signer. |
| Unsupported preparation | The operation is a swap, lookup-table custom transaction, or hosted recovery. | Use a supported operation or the appropriate direct protocol integration. |

## SDK example

Use [Client setup](/developer-sdk/integration-paths). The examples use two Ed25519
members. `signAndSubmit` / `sign_and_submit` is your application's helper; it signs,
submits, and waits for confirmation. Rust inputs use native `Pubkey` values.

### Create the set and add its role

Confirm set creation before adding its role. This role needs both System Program
access and a one-time SOL budget; each successful transfer reduces that budget.
After adding the role, read its assigned ID for the Rust operation below.

<CodeGroup>

```typescript TypeScript
import { SystemProgram } from '@solana/web3.js';

const createdSet = await swig.participantSets.create({
  swigConfigAddress,
  feePayer,
  threshold: 2,
  members: [
    { ed25519: { publicKey: participantAPublicKey } },
    { ed25519: { publicKey: participantBPublicKey } },
  ],
});

await signAndSubmit(createdSet.transaction);

const wallet = swig.wallets.use(swigConfigAddress, {
  requesterAuthority: {
    ed25519: { publicKey: adminPublicKey },
  },
});
const addRole = await wallet.roles.add({
  feePayer,
  authority: {
    participantSet: { address: createdSet.participantSetAddress },
  },
  actions: [
    {
      type: 'program',
      programId: SystemProgram.programId.toBase58(),
    },
    { type: 'solLimit', amount: 1_000_000n },
  ],
});

await signAndSubmit(addRole);
```

```rust Rust

        },

            WalletPermission::Program {
                program_id: Pubkey::from_str_const("11111111111111111111111111111111"),
            },
            WalletPermission::SolLimit { amount: 1_000_000 },
        ],
    })
    .await?;

sign_and_submit(add_role).await?;
```

### Prepare an operation

<CodeGroup>

```typescript TypeScript
const participantWallet = swig.wallets.use(swigConfigAddress, {
  requesterAuthority: {
    participantSet: { address: createdSet.participantSetAddress },
  },
});

const prepared = await participantWallet.transfer.sol({
  feePayer,
  destination,
  amount: 1_000n,
});

const plan = prepared.participantSetApprovalPlan;
if (!plan) throw new Error('ParticipantSet approval plan is missing');
```

```python Python
participant_wallet = swig.wallets.use(
    swig_config_address,
    requester_authority={
        "participantSet": {"address": created_set.participant_set_address}
    },
)

prepared = await participant_wallet.transfer.sol(
    fee_payer=fee_payer,
    destination=destination,
    amount=1_000,
)

plan = prepared.participant_set_approval_plan
if plan is None:
    raise RuntimeError("ParticipantSet approval plan is missing")
```

```rust Rust
use swig_developer_sdk::{PrepareTransferSolArgs, WalletAuthority};

let prepared = wallet
    .prepare_transfer_sol(PrepareTransferSolArgs {
        swig_config_address,
        fee_payer,
        destination,
        amount: 1_000,
        requester_authority: WalletAuthority::ParticipantSet {
            address: created_set.participant_set_address,
            role_id: Some(role_id),
        },
    })
    .await?;
let plan = prepared
    .participant_set_approval_plan
    .as_ref()
    .ok_or("ParticipantSet approval plan is missing")?;
```

### Collect member approvals

Distribute each request to its member and collect the returned approval. The
TypeScript/Python examples keep both callbacks together to show the full flow.
For Rust, run the signer for each selected member's request from `plan.members`
and collect the results into `approvals`.

<CodeGroup>

```typescript TypeScript
import {
  createParticipantEd25519Signer,
  signParticipantSetApproval,
} from '@swig-wallet/developer-sdk/signers';

const memberSigners = new Map([
  [
    participantAPublicKey,
    createParticipantEd25519Signer({
      publicKey: participantAPublicKey,
      signMessage: participantASignMessage,
    }),
  ],
  [
    participantBPublicKey,
    createParticipantEd25519Signer({
      publicKey: participantBPublicKey,
      signMessage: participantBSignMessage,
    }),
  ],
]);

const approvals = await Promise.all(
  plan.members.map(async (request) => {
    if (!('ed25519' in request.authority)) {
      throw new Error('Expected an Ed25519 ParticipantSet member');
    }
    const signer = memberSigners.get(request.authority.ed25519.publicKey);
    if (!signer) throw new Error('Approval plan returned an unknown member');
    return signParticipantSetApproval(request, signer);
  }),
);
```

```python Python
from swig_developer_sdk.signers import (
    create_participant_ed25519_signer,
    sign_participant_set_approval,
)

member_signers = {
    participant_a_public_key: create_participant_ed25519_signer(
        public_key=participant_a_public_key,
        sign_message=participant_a_sign_message,
    ),
    participant_b_public_key: create_participant_ed25519_signer(
        public_key=participant_b_public_key,
        sign_message=participant_b_sign_message,
    ),
}

approvals = []
for request in plan.members:
    authority = request.authority.get("ed25519")
    if authority is None:
        raise RuntimeError("Expected an Ed25519 ParticipantSet member")
    public_key = authority["publicKey"]
    signer = member_signers.get(public_key)
    if signer is None:
        raise RuntimeError("Approval plan returned an unknown member")
    approvals.append(await sign_participant_set_approval(request, signer))
```

```rust Rust
use std::sync::Arc;

use swig_developer_sdk::{Ed25519ParticipantSigner, ParticipantSigner};

let signer = Ed25519ParticipantSigner::new(Arc::clone(&keypair));
let approval = signer.approve(request).await?;
```

</CodeGroup>

Ed25519 signs the decoded challenge. The secp256k1 participant helper signs its
lowercase hexadecimal form with EIP-191. The Rust P-256 participant helper creates
a software WebAuthn proof; it does not establish browser user presence.
Use application-owned credential selection and RP ID/origin checks for passkeys.

### Compile and submit

Compilation validates the approvals and simulates the transaction. It does not
sponsor, broadcast, or confirm it.

<CodeGroup>

```typescript TypeScript
const compiled = await swig.transactions.compileParticipantSetApprovals({
  preparedTransaction: prepared,
  approvals,
});

console.log(compiled.authorizationExpirationSlot);
await signAndSubmit(compiled.transaction);
```

```python Python
compiled = await swig.transactions.compile_participant_set_approvals(
    prepared_transaction=prepared,
    approvals=approvals,
)

print(compiled.authorization_expiration_slot)
await sign_and_submit(compiled.transaction)
```

```rust Rust
use swig_developer_sdk::CompileParticipantSetApprovalsArgs;

let compiled = wallet
    .compile_participant_set_approvals(CompileParticipantSetApprovalsArgs {
        prepared_transaction: prepared,
        approvals,
    })
    .await?;
```

</CodeGroup>

Add remaining [Solana signatures](/developer-sdk/signers#ed25519-and-application-defined-signers)
after compilation, then submit before `authorizationExpirationSlot` /
`authorization_expiration_slot`. Use [Paymaster](/developer-sdk/sponsor-and-submit)
for sponsorship. Keep approvals with their original plan and nonce.
