## Introduction

Finance operations fund wallets, move assets, stake SOL, or pay transaction fees.
Use the guides below for the lifecycle of each operation. A prepared transaction
is a proposal; the wallet authority authorizes it before submission.

## SDK examples

### Prepare a wallet transfer

Use an existing wallet handle with its requester authority. Select the intended fee payer during preparation.

<CodeGroup>

```typescript TypeScript
const prepared = await wallet.transfer.sol({
  feePayer, destination, amount: 1_000_000n,
});
```

```python Python
prepared = await wallet.transfer.sol(
    fee_payer=fee_payer, destination=destination, amount=1_000_000,
)
```

```rust Rust
use swig_developer_sdk::PrepareTransferSolArgs;

let prepared = wallet.prepare_transfer_sol(PrepareTransferSolArgs {
    swig_config_address, fee_payer, requester_authority,
    destination, amount: 1_000_000,
}).await?;
```

</CodeGroup>

### Track the wallet balance

After chain confirmation, use indexed balances for the portfolio view. Index updates may arrive later than confirmation.

<CodeGroup>

```typescript TypeScript
const balances = await wallet.listTokenBalances();
```

```python Python
balances = await wallet.list_token_balances()
```

```rust Rust
let balances = wallet.list_token_balances(&swig_config_address).await?;
```

</CodeGroup>

## Input

| Flow | Input / choice |
| :--- | :--- |
| [Ramp](/developer-sdk/ramp) | Fiat/crypto amount, route, customer context, and a persisted order request ID. |
| [Transfer](/developer-sdk/transfers-and-swaps) | SOL/token amount and recipient; group multiple transfers when needed. |
| [Swap](/developer-sdk/swaps-and-batches) | Input/output assets, exact amount, and slippage limit. |
| [Yield](/developer-sdk/yield) | Validator, delegated principal, and a role allowed to stake. |
| [Paymaster](/developer-sdk/sponsor-and-submit) | Configured fee payer and signed transaction; retain the sponsorship idempotency key. |
| [x402](/developer-sdk/x402) | Approved payment challenge and facilitator-supported wallet transaction. |

## Output

| Result | Meaning |
| :--- | :--- |
| Prepared transaction | Unsigned transaction plus signer metadata; complete [Signing](/developer-sdk/signers) or [Participant set](/developer-sdk/participant-sets). |
| Submission identifier | Track chain confirmation separately from request acceptance. |
| Ramp order | Checkout and settlement lifecycle separate from the sell transfer. |
| Indexed balance or position | A recorded view, potentially behind the latest chain state. |

## Errors

| Error | Meaning |
| :--- | :--- |
| Permission failure | The acting role must permit the relevant programs and asset movement. |
| Funding failure | Wallet principal, transaction fees, and account rent have separate funding requirements. |
| Uncertain submission | Reconcile the existing attempt before creating another payment or order. |
