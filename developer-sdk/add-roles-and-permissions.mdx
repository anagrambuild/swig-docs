## Introduction

A role combines an authority with the actions it may perform. Use a separate
role for each person, service, or participant set that needs wallet access.
This lets an administrator grant a spending budget without sharing root access.

Adding a role prepares a transaction. The existing administrator signs it;
the new authority becomes usable after confirmation.

## Input

| Operation | Parameter | Description |
| :--- | :--- | :--- |
| Both | Wallet config address and network | Existing wallet, selected through the configured client |
| Add | `requesterAuthority` / `requester_authority` | Existing Ed25519 or secp256r1 authority with `manageAuthority` or `all` |
| Add | `feePayer` / `fee_payer` | Public key paying the fee |
| Add | `authority` | New Ed25519, secp256k1, secp256r1, or ParticipantSet authority |
| Add | `actions` | At least one typed [permission](/developer-sdk/permissions) |

TypeScript/Python use public-key strings. Rust uses `Pubkey` for Ed25519 and
compressed 33-byte SEC1 keys for secp256k1/secp256r1. A new ParticipantSet
role takes the set address without a role ID (`role_id: None` in Rust).
Swig assigns the new role ID.

## Output

TypeScript fields are shown below; Python uses snake_case names. Use the read
after confirmation to verify the grant. Saved policy metadata is separate.

| Field | Meaning |
| :--- | :--- |
| `swigConfigAddress`, `walletAddress` | Wallet configuration and asset-holding address |
| `roles[].roleId` | Assigned role identifier |
| `roles[].authorityType`, `authorityValue` | Encoded authority type and value |
| `roles[].actions` | Action index, action code, and stored action data for each grant |

Rust returns native typed authority and permission values through its role-list
result. Use the returned role ID when preparing an operation for a participant set.

## Errors

| Failure | Cause | What to do |
| :--- | :--- | :--- |
| Requester cannot add the role | Its authority type or management permission is unsupported. | Use an existing Ed25519 or secp256r1 administrator with manageAuthority or all. |
| Invalid new-role input | The action list is empty or the new authority is malformed. | Supply at least one supported action and a valid public authority. |
| New authority is not usable yet | Preparation alone has not installed the role. | Sign, submit, and confirm the add-role transaction before using it. |

## SDK example

### Add a scoped SOL-transfer role

This role can invoke the System Program and spend a total of 1,000,000 lamports.
Both actions are required: program access and asset spending are checked
separately. Each successful transfer reduces the remaining one-time budget.

Use the clients from [Client setup](/developer-sdk/integration-paths).
`signAndSubmit` / `sign_and_submit` is your application's signing, submission,
and confirmation helper, not an SDK method. Rust address inputs are `Pubkey` values.

<CodeGroup>

```typescript TypeScript
import { SystemProgram } from '@solana/web3.js';

const wallet = swig.wallets.use(swigConfigAddress, {
  requesterAuthority: {
    ed25519: { publicKey: adminPublicKey },
  },
});

const prepared = await wallet.roles.add({
  feePayer,
  authority: {
    ed25519: { publicKey: newRolePublicKey },
  },
  actions: [
    {
      type: 'program',
      programId: SystemProgram.programId.toBase58(),
    },
    { type: 'solLimit', amount: 1_000_000n },
  ],
});

await signAndSubmit(prepared);
```

```python Python
from solders.system_program import ID as SYSTEM_PROGRAM_ID
from swig_developer_sdk import ProgramAction, SolLimitAction

wallet = swig.wallets.use(
    swig_config_address,
    requester_authority={
        "ed25519": {"publicKey": admin_public_key}
    },
)

prepared = await wallet.roles.add(
    fee_payer=fee_payer,
    authority={
        "ed25519": {"publicKey": new_role_public_key}
    },
    actions=(
        ProgramAction(program_id=str(SYSTEM_PROGRAM_ID)),
        SolLimitAction(amount=1_000_000),
    ),
)

await sign_and_submit(prepared)
```

```rust Rust
use solana_pubkey::pubkey;
use swig_developer_sdk::{PrepareAddRoleArgs, WalletAuthority, WalletPermission};

let prepared = wallet
    .prepare_add_role(PrepareAddRoleArgs {
        swig_config_address,
        fee_payer,
        requester_authority: WalletAuthority::Ed25519 {
            public_key: admin_public_key,
        },
        authority: WalletAuthority::Ed25519 {
            public_key: new_role_public_key,
        },
        actions: vec![
            WalletPermission::Program {
                program_id: pubkey!("11111111111111111111111111111111"),
            },
            WalletPermission::SolLimit { amount: 1_000_000 },
        ],
    })
    .await?;
```

</CodeGroup>

### Confirm the role

After the add-role transaction confirms, inspect the assigned authority and actions.

<CodeGroup>

```typescript TypeScript
const { roles } = await wallet.roles.list();
console.log(roles);
```

```python Python
roles_result = await wallet.roles.list()
print(roles_result.roles)
```

```rust Rust
let roles_result = wallet.list_roles(&swig_config_address).await?;
```

</CodeGroup>

Complete embedded signature requests and all required Solana transaction
signatures before submission. See [Signing](/developer-sdk/signers) or
[Participant set](/developer-sdk/participant-sets) for threshold approval.
