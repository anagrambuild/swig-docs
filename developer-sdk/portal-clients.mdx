---
title: "Legacy and Low-Level Clients"
---

Swig currently has three TypeScript surfaces related to the developer portal.
They overlap, but they are not the same product.

## Client comparison

| Package | Status | Best use | Policy access | Transaction access | Response model |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `@swig-wallet/developer-sdk` | current | prepare-first hosted wallet flows | `swig.wallets.getPolicy()` returns raw policy metadata | wallet creation, transfers, swaps, recovery, sponsor flow | prepared transactions and signing metadata |
| `@swig-wallet/developer` | legacy | existing portal integrations that depend on rich helper models | `client.getPolicy()` returns `Policy`, `Actions`, and `AuthorityInfo` helpers | `createWallet()` only | throws `SwigError` |
| `@swig-wallet/api` | low-level | direct portal and paymaster endpoint access | `client.policies.get()` returns raw policy JSON | `wallet.create()`, `paymaster.sign()`, `paymaster.sponsor()` | returns `{ data, error }` |

## Which one should you start with

Use `@swig-wallet/developer-sdk` first if your goal is to:

- create wallets through backend-prepared transactions
- keep the API key on the server
- return prepared transactions to browser or mobile clients
- build Next.js or NestJS proxy routes around Swig actions

## Important nuance

`@swig-wallet/developer-sdk` does expose `swig.wallets.getPolicy(policyId)` and
the exported `Policy` type because wallet creation and recovery flows depend on
policy metadata.

That still does not make it the rich policy-helper SDK. If you need
`Actions.canSpendSol()`, `AuthorityInfo.isSession()`, or a portal-centric
policy client, that is still legacy `@swig-wallet/developer` territory.

## Package fit

- Use `@swig-wallet/developer-sdk` for new hosted wallet integrations.
- Use `@swig-wallet/api` when you want raw portal and paymaster endpoints.
- Keep `@swig-wallet/developer` for existing integrations that already depend on
  its richer policy models and helper methods.

Treat `@swig-wallet/developer` as deprecated for new integrations.

If you are deciding what to teach first in the docs, treat `developer-sdk` as
the primary Swig Developer SDK, `developer` as the legacy developer SDK, and
`api` as the low-level portal client.
